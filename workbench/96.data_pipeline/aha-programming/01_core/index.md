# 이 섹션은

AHA(Avoid Hasty Abstractions) 프로그래밍의 근본적인 원칙과 철학을 설명한다. 
- 이 섹션의 카드는 맹목적인 DRY(Don't Repeat Yourself) 원칙 추구가 어떻게 잘못된 추상화를 낳고 시스템을 망가뜨리는지 분석한다.
- 실무 개발 과정에서 언제 코드를 중복시키고 언제 공통화해야 하는지에 대한 판단 기준을 제공하여, 유연한 아키텍처 설계를 돕는다.
