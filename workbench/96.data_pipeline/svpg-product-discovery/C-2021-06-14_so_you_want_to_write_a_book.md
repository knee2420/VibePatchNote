# summary
비즈니스 및 기술 서적을 집필하는 것은 소프트웨어를 만드는 것과 동일한 원리를 따른다. **독자가 겪는 진짜 고통(Problem)을 정의하고, 목차와 샘플 챕터(Prototype)를 만들어 피드백을 수집하며, 독자에게 명확한 가치를 전달할 수 있을 때까지 반복 검증**해야 한다.

| E2 | 원칙 | 독자 가치 중심(Value Focus) | 자신이 쓰고 싶은 이야기가 아니라 독자가 현장에서 직면한 난제를 해결하는 가치 중심 집필 | `# So You Want To Write a Book?` |
| E3 | 절차 | 반복적 피드백 루프 | 초고를 신뢰할 수 있는 업계 리더들에게 지속적으로 공유하며 논리의 결손을 교정 | `# So You Want To Write a Book?` |
| E4 | 안티패턴 | 독자 없는 밀실 집필 | 피드백 없이 수년간 혼자 책을 쓰다가 출간 후 시장에서 외면받는 워터폴 저술 | `# So You Want To Write a Book?` |

# 밖으로
- [E1] 지식 체계화와 프로토타입의 결합은 본 데이터 파이프라인의 구축 철학과도 직접 맞닿아 있다.
