# summary
많은 조직에서 디스커버리가 '더 두꺼운 요구사항 명세서(PRD)'를 쓰는 일로 변질되었다. **문서는 아무리 정교해도 인터랙션의 결함과 비즈니스 구멍을 숨기기 쉽다. 프로토타입과 유저 스토리 기반의 가벼운 기록을 통해 문서화 낭비를 제거**해야 한다.
