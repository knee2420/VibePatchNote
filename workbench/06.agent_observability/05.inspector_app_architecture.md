# [ARCH-06] 독립 Inspector 앱 아키텍처 및 런타임 규격서

- **문서 ID**: `ARCH-06-INSPECTOR-APP`
- **상태**: `Accepted` (방안 B 확정)
- **작성일자**: 2026-09-11
- **관련 문서**: [REQ-06 요구사항](./01.requirements.md), [SPEC-06 구현 사양](./02.specifications.md), [CONTRACT-06 데이터 계약](./03.data_contracts.md), [SPEC-06-INTF 인터페이스](./04.standard_interfaces.md)
- **목적**: 일반 사용자 웹 앱(`apps/web`)과 에이전트 관측 도구를 물리적으로 분리하여, **독립된 프로세스/터미널에서 구동되는 전용 엔지니어링 콘솔(`apps/inspector`)의 아키텍처와 인터페이스 규격**을 정의한다.

---

## 1. 아키텍처 결정 배경 (ADR: Architecture Decision Record)

### 1.1 결정 (Decision)
관리자 및 에이전트 관측 기능은 `apps/web` 내부에 섞지 않고, **독립된 웹 애플리케이션(`apps/inspector`, 패키지명 `@vibe/inspector`)으로 물리적으로 완전 분리**한다.

### 1.2 핵심 근거
1. **일반 프로덕션 번들 오염 위험 '원천 0%' (Zero Bundle Leaks)**:
   - `lazy()` 코드 스플리팅을 쓰더라도 발생할 수 있는 실수 정적 임포트(Static Import)나 빌드 청크 노출 위험을 원천 차단한다.
   - 일반 사용자 번들(`@vibe/web`)은 단 1바이트의 관리자 코드나 디버깅 로직도 포함하지 않는다.
2. **관심사의 완벽한 분리 (Separation of Concerns)**:
   - `apps/web`: 최종 사용자의 문서 편집, 와이어프레임 렌더링, 프로덕션 UX에 100% 집중.
   - `apps/inspector`: 프롬프트 역분해, 모델별 토큰/비용 벤치마크, 429 쿨다운 타이머, CLI Stderr 로그 등 **에이전트 엔지니어링 툴링**에 100% 집중.
3. **독립된 개발 주기와 경량성**:
   - 인스펙터 화면을 개발하거나 튜닝할 때 메인 웹 앱을 빌드하거나 재시작할 필요 없이, 전용 터미널에서 독립적으로 핫 리로딩(`HMR`)을 누린다.

## 2. 모노레포 프로세스 및 토폴로지 (Process Topology)

독립된 3개의 프로세스가 Turborepo 환경에서 상호 간섭 없이 구동된다.

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        Turborepo Workspace                             │
│                                                                        │
│   [Terminal 1]               [Terminal 2]              [Terminal 3]    │
│   apps/web (5173)            apps/inspector (5174)     apps/api (8000) │
│   일반 사용자 웹 에디터       에이전트 관측 콘솔        FastAPI & 엔진  │
│          │                         │                         │         │
│          │ (사용자 작업 요청)       │ (관측 API / SSE 구독)   │         │
│          └─────────────────────────┼─────────────────────────┘         │
│                                    ▼                                   │
│                       packages/agent-telemetry                         │
│                    (공통 데이터 계약 & 인터페이스 SSOT)                 │
└────────────────────────────────────────────────────────────────────────┘
```

### 포트 및 터미널 할당 정책
| 앱/서비스 | 디렉터리 경로 | 패키지명 | 실행 포트 | 역할 |
|---|---|---|---|---|
| **API Server** | `apps/api` | `@vibe/api` | `http://localhost:8000` | 에이전트 런타임, 파이프라인 구동, 관측 데이터 영속화 |
| **End-User Web** | `apps/web` | `@vibe/web` | `http://localhost:5173` | Tiptap 에디터, 최종 사용자 캔버스 화면 |
| **Agent Inspector** | `apps/inspector` | `@vibe/inspector` | `http://localhost:5174` | 파이프라인 타임라인, 프롬프트 해부, Fallback 관측 |

## 3. 독립 통신 인터페이스 규격 (Client-to-Host Protocol)

`apps/inspector`는 백엔드(`apps/api`) 내부 코드를 직접 알지 못하며, 오직 **표준 HTTP REST API**와 **SSE(Server-Sent Events) 스트림** 인터페이스만 소비한다.

```text
[apps/inspector (@vibe/inspector: 5174)]
      │
      ├── 1. HTTP REST ────▶ GET /api/v1/inspector/runs (실행 이력 목록)
      │                     GET /api/v1/inspector/runs/{id} (특정 실행 상세 트리/스냅샷)
      │                     GET /api/v1/inspector/matrix (엔진/환경 SSOT 매트릭스)
      │
      └── 2. SSE Stream ───▶ GET /api/v1/inspector/runs/{id}/events (실시간 실행 스트림)
```

### 3.1 REST API 인터페이스 상세

#### 1) 실행 세션 목록 조회
* **엔드포인트**: `GET /api/v1/inspector/runs`
* **Query Params**: `limit=50`, `status=failed|success`, `pipeline=OutlinePipeline`
* **Response**:
  ```json
  [
    {
      "run_id": "run_01j7x8k0...",
      "pipeline_name": "OutlinePipeline",
      "status": "success",
      "start_time": "2026-09-11T07:20:00.000Z",
      "total_latency_ms": 14920.0,
      "total_tokens": 4520,
      "primary_model": "gemini-3.5-flash",
      "had_fallback": true
    }
  ]
  ```

#### 2) 단일 실행 상세 (스팬 트리 + 스냅샷 완결본)
* **엔드포인트**: `GET /api/v1/inspector/runs/{run_id}`
* **Response**:
  ```json
  {
    "run_id": "run_01j7x8k0...",
    "pipeline_name": "OutlinePipeline",
    "status": "success",
    "spans": [
      {
        "span_id": "span_01...",
        "dotted_order": "20260911T072000000Zspan_01...",
        "name": "DocumentContextBuilder",

      {
        "attempt_index": 1,

      }

  }
  ```

#### 3) 엔진 & 런타임 SSOT 매트릭스
* **엔드포인트**: `GET /api/v1/inspector/matrix`
* **Response**: 등록된 공급자 카탈로그, CLI 바이너리 실존 상태, Fallback 라우팅 체인 설정.

---

### 3.2 SSE 실시간 이벤트 스트림 프로토콜
* **엔드포인트**: `GET /api/v1/inspector/runs/{run_id}/events`
* **헤더**: `Accept: text/event-stream`
* **이벤트 처리기(EventSource) 매핑**:
  - `span_start`: 타임라인에 새 막대기 노드 추가
  - `llm_chunk`: 활성 LLM 패널에 텍스트 실시간 타이핑 렌더링
  - `model_attempt_failed`: 실패 경고 알림 팝업 및 Fallback 배지 전환
  - `state_checkpoint`: 해당 단계의 도메인 스냅샷 탭 활성화
  - `span_end`: 해당 스팬 완료 처리 및 지연 시간/토큰 확정

## 4. 프론트엔드 타입 계약 공유 (`contracts`)

`apps/inspector`와 `apps/web`은 UI 구현체는 분리되지만, **데이터 타입 인터페이스는 100% 동일한 단일 소스(SSOT)**를 공유한다.

```text
packages/agent-telemetry/
  └── contracts/
        ├── span.py              (Pydantic v2 SSOT)
        ├── attempt.py
        └── snapshot.py
              │ (Codegen / Type Sync)
              ▼
packages/agent-telemetry/types/  (공통 TypeScript 정의)
        ├── span.d.ts
        └── index.d.ts
              ▲
              │ workspace:* 로 import
    ┌─────────┴─────────┐
    │                   │
apps/inspector       apps/web
```

## 5. 실행 및 개발 워크플로우 (Development Workflow)

`package.json`의 루트 스크립트를 통해 선택적으로 또는 동시에 구동할 수 있다.

```json
// 루트 package.json 스크립트 예시
{
  "scripts": {
    "dev": "turbo run dev --filter=@vibe/web --filter=@vibe/api",
    "dev:inspector": "turbo run dev --filter=@vibe/inspector --filter=@vibe/api",
    "dev:all": "turbo run dev --filter=@vibe/web --filter=@vibe/inspector --filter=@vibe/api"
  }
}
```

### 터미널 운용 시나리오
1. **일반 사용자 모드 개발 시**:
   `pnpm dev` 실행 ➔ 포트 5173(`apps/web`)과 포트 8000(`apps/api`)만 구동.
2. **에이전트 성능 튜닝 및 관측 집중 시**:
   `pnpm dev:inspector` 실행 ➔ 포트 5174(`apps/inspector`)와 포트 8000(`apps/api`)만 구동.
3. **통합 테스트 시**:
   `pnpm dev:all` 실행 ➔ 3개 프로세스 동시 구동.

## 6. 결론 및 향후 로드맵

방안 B(독립 앱 분리)를 확정함에 따라:
1. **`@vibe/web`의 안전성 확보**: 메인 서비스 번들이 절대 오염되지 않는 깨끗한 격리 달성.
2. **`@vibe/inspector`의 전문성 확보**: 일반 UI의 제약(FSD 레이어 규칙 등)에 얽매이지 않고, 오직 에이전트 관측/디버깅에 최적화된 고밀도 대시보드(React Flow, 타임라인 차트, 기하 캔버스)를 자유롭게 설계 가능.
3. **인터페이스 기반 표준화**: 백엔드와 인스펙터 간의 통신이 정형화된 REST/SSE 프로토콜로 완전히 규격화됨.
