# [06] Inspector 추상화 이행 로드맵

> **출처**: 「(SEO) Inspector 추상화하기」 제안 (2026-09-12) + 코드베이스 실측 감사
> **규칙 정본**: [`.agents/rules/60-data/observability.md`](../../.agents/rules/60-data/observability.md)
>
> **REQ-06 의 Phase 1~4 와 직교한다.** 그쪽은 *무엇을 보여줄 것인가* 의 순서이고,
> 이 문서는 *무엇을 고쳐야 그것이 가능한가* 의 순서다. 혼동을 피해 `A0~A5` 로 표기한다.
>
> 이 문서는 **계획서**다. 코드는 아직 손대지 않았다.

## 1. 목표

워크플로우가 추가·변경되어도 Inspector 가 코드 수정 없이 이를 인식하고 시각화한다
(Zero-config Observability). 원 제안의 표현으로는 **추적 주도형 아키텍처**.

## 2. 원 제안의 진위 판정

| 절 | 제안 | 판정 | 실측 근거 |
| --- | --- | --- | --- |
| §1 | Telemetry 규격화 · 추적 없는 로직 금지 | ✅ 맞다. **심각도는 과소평가** | `StepCollector` 사용처가 `outline/pipeline.py` **1곳뿐**. `ScaffoldPipeline` 은 A/B/C/D 4단계를 돌면서 계측 0, 제안이 금지하라던 `logger.info("[pipeline] A 측정 %.2fs")` 로만 상태를 남긴다. 위반이 예외가 아니라 기본값이다 |
| §2 | 선언적 워크플로우 · DAG | ⚠️ **진단 맞고 처방 과함** | `core/pipeline.py` 가 절차적인 건 사실. 그러나 저장된 스팬 8개가 **전부 `parent_span_id=None`** — 계층도 분기도 없는 선형이다. `dotted_order` 와 부모 스택으로 **그래프 표현 능력은 이미 있고 쓰이지 않을 뿐**이다. 지금 필요한 건 StateGraph 가 아니라 Manifest 추출 |
| §3 | I/O 컨트랙트 스키마화 | ✅ 맞다. **실효 가장 큼** | `inputs`/`outputs` 가 `Dict[str, Any]` 라서 Inspector 가 `val.length > 80 \|\| val.includes('\n')` 으로 타입을 추측한다 |
| §4 | 도메인 중립 UI | ✅ 맞다 | 타입 어휘 자체가 불일치. 백엔드 `SpanType` 5종 / 프론트 7종(`workflow`·`custom` 추가), 제안이 요구한 `router`·`condition` 은 **양쪽 어디에도 없다** |
| 요약 | *"먼저 `contracts/span.py` 를 고도화하라"* | ❌ **틀리다** | 아래 |

### 2-1. 요약 권고가 틀린 이유

계약은 이미 옳다. **[`03.data_contracts.md`](./03.data_contracts.md) 가 정확한 규격을
이미 정해뒀고, 구현이 그것을 어겼다.**

| | 사양서 (`03.data_contracts.md`) | 구현 (`apps/inspector/src/types.ts`) |
| --- | --- | --- |
| `SpanStatus` | §3 `'pending' \| 'running' \| 'success' \| 'failed' \| 'skipped'` | `'SUCCESS' \| 'FAILED' \| 'FALLBACK_TRIGGERED' \| 'CANCELLED' \| 'RUNNING'` |
| `ModelAttemptRecord` | §3 `model_name` · `latency_ms` · `usage: SpanUsage` | `model` · `duration_ms` · `input_tokens` · `cost_usd` · `raw_command` |

결과:

- 저장된 값이 `"success"` 소문자인데 `SpanDetail` 이 `=== 'SUCCESS'` 로 비교한다.
  **성공한 스팬이 전부 실패 색으로 렌더된다.**
- Attempts 탭이 `att.duration_ms.toFixed(1)` 을 호출한다. 실제 레코드에 그 필드가 없다.
  → `TypeError`. `main.tsx` 에 ErrorBoundary 가 없어 **앱 전체가 백화면**이 된다.
  (재현: attempt 가 있는 run 2건 중 하나의 LLM 스팬 → "시도 이력" 탭)

> 그러므로 A0 은 "계약을 더 만드는 것"이 아니라 **"이미 옳은 계약을 강제하는 것"** 이다.
> `.agents/rules/README.md` 의 원칙과 같다 — *"문서만 있고 강제 수단이 없는 규칙은 지켜지지 않는다."*

## 3. 제안이 놓친 것

### 3-1. 🔴 같은 실행을 기록하는 체계가 셋이고 서로를 모른다

```text
전체 run 디렉터리 : 54
  events.jsonl    : 51      core/agent_runtime      status: completed/failed   RunCost
  meta.json       : 17      core/llm/tracer         status: success/failed     SpanUsage
  둘 다           : 15      같은 실행이 이중 기록
월별 원장 엔트리  : 43      LocalLedger             status: SUCCESS/TIMEOUT    RunCost
```

**Inspector 는 54건 중 17건만 보여준다.** 원장에만 있는 `TIMEOUT` 4건·`FAILED` 1건은
화면에 없다 — 관측 도구가 가장 봐야 할 기록이다.

이 분기는 **사양서가 예견하지 못했다.** `agent_runtime` 은 사양서에 서브시스템이 아니라
`agent_runtime: "agy-cli 2.0"` 이라는 *문자열 필드명*으로만 등장한다. 소유 경계를
정한 문서가 없어서 두 체계가 같은 디렉터리에 각자 자랐다.

→ 경계는 [`60-data/observability.md`](../../.agents/rules/60-data/observability.md) §2 에서 확정했다.

### 3-2. 🔴 Inspector API 스키마는 이미 "다른 모델"로 설계돼 있다

`app/inspector/schemas.py` 의 `RunSummaryResponse` 필드는
`input_tokens` / `output_tokens` / `thinking_tokens` / `cache_read_tokens` —
`SpanUsage` 가 아니라 **`agent_runtime.RunCost` 그대로**다.

그런데 `InspectorService` 는 `tracer` 의 `meta.json` 을 읽는다. `meta.json` 에는
`usage` 키가 아예 없어서:

```python
usage = meta.get("usage", {})              # 항상 {}
thinking_tokens   = usage.get(...)  → 0
cache_read_tokens = usage.get(...)  → 0
cost_usd          = usage.get(...)  → 0.0
```

**정확한 값은 이미 원장에 있다.** `{"cost": {"cacheReadTokens": 16288, ...}}`
디스크에 16288 이 적혀 있는데 화면엔 0 이 뜬다. 읽을 데이터가 없는 게 아니라
**잘못된 파일을 읽고 있다.**

> 예외: `cost_usd` 는 진짜로 어디에도 없다. `ModelSpec` 에 단가 축이 없어
> 시스템 전체에 USD 비용이 존재하지 않는다.

### 3-3. 🟠 원장 파일 안에서도 스키마가 갈라져 있다

같은 `2026-09.jsonl` 안에 `recordedAt`/`runId`(11건)과 `recorded_at`/`run_id`(32건)이
섞여 있다. `LedgerEntry` 에 alias 가 없어 앞의 11건은 검증을 통과하되 **모든 필드가
기본값으로 덮이며 조용히 유실**된다.

## 4. 이행 단계

### A0 — 강제 수단 부착 · 어휘 통일 ★ 선행

| | |
| --- | --- |
| **목표** | 이미 옳은 계약이 다시 어긋나지 못하게 한다 |
| **선행** | 없음 |

- `A0-1` **Python 계약 → TS 타입 자동 생성.** 수기 `types.ts` 폐기.
  OpenAPI → `openapi-typescript`, 또는 Pydantic → `datamodel-code-generator`.
  생성물과 커밋본의 diff 를 CI 가 비교
- `A0-2` 상태 어휘 소문자로 통일. `FALLBACK_TRIGGERED` 는 상태에서 제거하고
  `len(attempts) > 1` 로 유도
- `A0-3` 토큰 어휘를 `SpanUsage` 로 수렴. `SpanUsage` 에 `cache_read_tokens` 추가,
  `RunCost` 흡수
- `A0-4` 월별 원장 camelCase 11건 마이그레이션 (`migrations/`, `STORAGE_VERSION` 증가).
  읽기 시점 폴백 금지 — `60-data/rule.md` §5
- `A0-5` `cost_usd` 를 `float | None` 으로. 0.0 은 "무료"라는 거짓말
- `A0-6` `test_inspector.py` 의 합성 픽스처를 **실제 `ingest_pipeline_telemetry()` 출력**으로
  교체. 현재 `status:"SUCCESS"`·`duration_ms` 라는 **생산자가 쓰지 않는 키**로 통과 중이라
  이 버그가 살아남았다

**완료 판정**: 생성 타입과 커밋본이 일치하고, 대문자 상태 표기가 저장소 어디에도 없다.

### A2 — 문자열 결합 제거 ★ 추상화의 실질

| | |
| --- | --- |
| **목표** | 프론트가 백엔드 파일 경로를 모르게 한다 |
| **선행** | A0 |

현재 `data_via` 는 손으로 쓴 문자열이고
(`"context_builder.py (DocumentContextBuilder.build_context)"`), 프론트가 이를
정규식으로 되파싱해 `KNOWN_FILE_PATHS` 하드코딩 테이블과 대조한다.

이미 깨져 있다 — `KNOWN_FILE_PATHS['schema.py']` 가 존재하지 않는 경로를 가리키고,
`/source` 가 basename glob + **파일 크기 내림차순** 으로 폴백해
`apps/api/venv/Lib/site-packages/pydantic/v1/schema.py` 를 반환한다.
이 노드는 **모든 run 의 post-LLM 검증 스팬에 있다.**

- `A2-1` `data_via: List[str]` → `List[SpanSource]` (`module`·`qualname`·`file`·`lineno`).
  **`inspect` 로 자동 수집한다. 손으로 쓰지 않는다**
- `A2-2` `KNOWN_FILE_PATHS` 전체 삭제, `parseViaItem` 정규식 삭제
- `A2-3` `/source` 를 정확 경로 조회로 재작성. 현재 basename glob 이
  `node_modules`+`venv` 를 훑어 **요청당 1.4초**(실측). 트리 노드 하나 펼칠 때마다 발생
- `A2-4` `SpanType` 에 `router`·`condition` 추가, 프론트 `workflow`·`custom` 과 어휘 일치
- `A2-5` 중첩 스팬 실사용 — `dotted_order` 계층을 워터폴에 실제로 렌더

**완료 판정**: `apps/inspector/src` 에 백엔드 파일 경로 리터럴이 0개.

## 6. 열린 결정 — 착수 전 확정 필요

1. **`meta.json` 을 유지할 것인가.** A1 이후 목록의 근거가 아니게 된다.
   `ledger.jsonl` 요약 캐시로 남길지, 없앨지
2. **USD 비용을 실제로 계산할 것인가.** 계산하면 `ModelSpec` 에 단가 축 추가가 선행.
   안 하면 필드를 `None` 으로 두고 UI 에서 숨긴다
3. **`apps/inspector` 를 FSD 로 맞출 것인가.** 현재 `src/components/` 평면,
   `httpClient` 대신 raw `fetch` — AGENTS.md 규칙 4·5 위반이지만 린트가 안 돌아 안 걸린다.
   `apps/web` 과 같은 규칙을 적용할지, 내부 도구로 예외를 명문화할지
4. **A2-1 의 `SpanSource` 자동 수집 범위.** `inspect` 로 호출 스택 전체를 뜨면
   무겁다. 데코레이터가 선언한 지점만 남길지

> 원 제안의 PoC 권고("워크플로우 하나를 골라 규격을 맞춘다")는 옳다.
> 다만 **대상을 바꾼다** — outline 은 이미 계측돼 있으므로 새로 배울 것이 없다.
> **계측 0 인 `ScaffoldPipeline` 이 진짜 시험대다** (A3-2).
