## 1. 아키텍처 원칙: 독립 공통 패키지 분리

모노레포의 **호스트 비의존 헌법(P1)**을 수호하고 엔진 간의 불필요한 결합을 원천 차단하기 위해, 계측 및 인터페이스는 독립된 순수 라이브러리 패키지(`packages/agent-telemetry`)로 관리한다.

```text
                     packages/agent-telemetry
              (순수 인터페이스 & 데이터 계약, 외부 의존성 0)
              ┌─────────────────────────────────────────┐
              │ • contracts/ (Span, Attempt, Snapshot)  │
              │ • collector/ (StepCollector & Context)  │
              │ • harness/   (BaseLlmHarness & Fallback)│
              └────────────────────┬────────────────────┘
                                   │ import (단방향 참조)
         ┌─────────────────────────┼─────────────────────────┐
         ▼                         ▼                         ▼
packages/scaffold-engine    packages/document-viewer       apps/api (호스트)
(아웃라인/스캐폴드 엔진)      (문서 뷰어/변환 엔진)         (FastAPI 트레이서 & UI 전송)
```

### 왜 독립 패키지여야 하는가?
1. **엔진 간 결합 방지**: `document-viewer`나 제3의 엔진이 계측을 위해 `scaffold-engine`을 엉뚱하게 참조하는 참사를 방지한다.
2. **호스트 비의존성(P1) 유지**: FastAPI나 데이터베이스에 전혀 의존하지 않으므로, CLI 환경이나 단위 테스트(`pytest`)에서도 엔진 단독으로 계측 데이터를 생성할 수 있다.
3. **신규 어댑터 확장 표준화**: 신규 모델/CLI가 추가되더라도 `BaseLlmHarness` 규격만 상속받으면 자동으로 텔레메트리와 Fallback 지원을 획득한다.

## 2. 인터페이스 1: 파이프라인 계측 인터페이스 (`StepCollector`)

엔진 내부에서 복잡한 시간 측정, 에러 핸들링, 딕셔너리 조립을 수동으로 하지 않고, `with` 구문으로 각 공정을 안전하게 감싸는 표준 인터페이스이다.

### 2.1 클래스 시그니처 및 메서드 규약

```python
from __future__ import annotations
from contextlib import contextmanager
from typing import Any, Dict, Generator, Optional
from packages.agent_telemetry.contracts import (
    SpanType,
    SpanRecord,
    StageSnapshotRecord,
    PipelineTelemetry,
)

class StepScope:
    """단일 실행 단계(Span)의 계측 컨텍스트"""

    def set_inputs(self, inputs: Dict[str, Any]) -> None:
        """해당 단계의 입력 매개변수 기록"""
        ...

    def set_outputs(self, outputs: Dict[str, Any]) -> None:
        """해당 단계의 정상 산출물 기록"""
        ...

    def attach_harness_result(self, exec_res: Any) -> None:
        """LLM 하네스 실행 결과(토큰, attempts, CLI 메타)를 스팬에 결합"""
        ...

    def snapshot(self, stage_id: str, stage_name: str, payload: Dict[str, Any]) -> None:
        """[FR-02, FR-07-3] 해당 단계의 도메인 상태를 스냅샷으로 캡처"""
        ...


class StepCollector:
    """파이프라인 전체 생명주기 동안 Span과 Snapshot을 수집하는 불변 수집기"""

    def __init__(self, pipeline_name: str, trace_id: Optional[str] = None) -> None:
        ...

    @contextmanager
    def step(
        self,
        name: str,
        span_type: SpanType = SpanType.CHAIN,
        parent_scope: Optional[StepScope] = None,
    ) -> Generator[StepScope, None, None]:
        """단일 작업을 계측하는 컨텍스트 매니저.
        
        - 진입 시: start_time, dotted_order 자동 생성
        - 정상 종료 시: end_time, latency_ms 계산 및 status='success' 확정
        - 예외 발생 시: status='failed', stack_trace 및 error 자동 캡처 후 예외 re-raise
        """
        ...

    def export_telemetry(self, provenance: Dict[str, Any]) -> PipelineTelemetry:
        """수집 완료된 모든 Span, Attempt, Snapshot을 정형 계약 객체로 패키징"""
        ...
```

## 3. 인터페이스 2: LLM 멀티 엔진 드라이버 인터페이스 (`BaseLlmHarness`)

CLI 서브프로세스, 클라우드 REST API, 로컬 추론 서빙 등 **어떤 실행 프로토콜이든 동일한 메서드로 호출하고 계측할 수 있도록 규격화**하는 인터페이스이다.

### 3.1 `BaseLlmHarness` 추상 클래스 명세

```python
from abc import ABC, abstractmethod
from typing import Any, Dict, List, Optional
from pathlib import Path
from packages.agent_telemetry.contracts import (
    ExecutionProtocol,
    ModelAttemptRecord,
    SpanUsage,
)

class LlmExecutionResult:
    """하네스 실행 완료 객체 (표준화)"""
    model: str
    status: str                         # SUCCESS | FAILED
    structured_output: Optional[Dict[str, Any]]
    raw_response: Optional[str]
    usage: SpanUsage
    attempts: List[ModelAttemptRecord]  # 1차, 2차, 3차... 시도 내역 완결 누적
    telemetry_metadata: Dict[str, Any]
    error: Optional[str]


class BaseLlmHarness(ABC):
    """모든 LLM 엔진/어댑터의 공통 부모 인터페이스"""

    def __init__(
        self,
        model: str,
        timeout_seconds: int = 180,
        fallback_providers: Optional[List[BaseLlmHarness]] = None,
    ) -> None:
        self.model = model
        self.timeout_seconds = timeout_seconds
        self.fallback_providers = fallback_providers or []

    @property
    @abstractmethod
    def execution_protocol(self) -> ExecutionProtocol:
        """엔진의 실행 방식 (CLI_SUBPROCESS | DIRECT_REST_API | LOCAL_SERVING)"""
        ...

    @abstractmethod
    def _execute_single_attempt(
        self,
        prompt: str,
        schema_path: Optional[Path],
        file_path: Optional[Path],
        **kwargs: Any,
    ) -> LlmExecutionResult:
        """각 하네스 드라이버가 구현해야 하는 실제 1회 호출 단위"""
        ...

    def run_structured(
        self,
        prompt: str,
        schema_path: Optional[Path] = None,
        file_path: Optional[Path] = None,
        **kwargs: Any,
    ) -> LlmExecutionResult:
        """[템플릿 메서드] Fallback 오케스트레이션과 Attempt 수집을 자동 수행한다.
        
        1. 1순위(자신)의 `_execute_single_attempt` 호출.
        2. 성공 시 -> `ModelAttemptRecord(status='SUCCESS')` 추가 후 즉시 반환.
        3. 실패 시 -> `ModelAttemptRecord(status='FAILED', error=...)` 추가 후,
           등록된 `fallback_providers` 목록 순서대로 자동 페일오버 진행.
        4. 최종 시도까지의 모든 attempts 이력을 `LlmExecutionResult`에 담아 반환.
        """
        ...
```

### 3.2 CLI 서브프로세스 어댑터 표준 규약 (`CliSubprocessDriver`)
CLI 기반 엔진(`agy`, `gpt-cli`, `claude-cli`)을 만들 때는 다음 서브프로세스 표준 규약을 준수해야 한다:

1. **상위 컨텍스트 주입**:
   부모 스팬의 `VIBE_TRACE_ID`, `VIBE_PARENT_SPAN_ID`, `VIBE_PARENT_DOTTED_ORDER`를 환경변수로 자식 프로세스에 주입.
2. **에러 버퍼 격리**:
   `stderr` 파이프를 별도 버퍼에 누적하여 크래시 발생 시 `SpanError.stderr`에 보존.
3. **벽시계(Wall-clock) vs 엔진 시간 분리**:
   OS 프로세스 기동 오버헤드를 추적하기 위해 백엔드 실측 시간과 CLI 내부 보고 시간을 분리 캡처.

## 4. 인터페이스 3: 엔진 ➔ 호스트 패키지 경계 인터페이스 (`ABI Contract`)

엔진(`scaffold-engine` 등)이 작업을 마치고 호스트 앱(`apps/api`)에 데이터를 반환할 때의 인터페이스 규약이다.

```python
# packages/agent-telemetry/contracts/telemetry.py
from pydantic import BaseModel, Field
from typing import List, Dict, Any
from packages.agent_telemetry.contracts.span import SpanRecord
from packages.agent_telemetry.contracts.attempt import ModelAttemptRecord
from packages.agent_telemetry.contracts.snapshot import StageSnapshotRecord

class PipelineTelemetry(BaseModel):
    """엔진이 호스트로 방출하는 완결 텔레메트리 계약 패키지"""
    pipeline_name: str
    trace_id: str
    provenance: Dict[str, Any]
    spans: List[SpanRecord] = Field(default_factory=list)
    attempts: List[ModelAttemptRecord] = Field(default_factory=list)
    snapshots: List[StageSnapshotRecord] = Field(default_factory=list)
```

### 호스트 수신부 (`apps/api/app/core/llm/tracer.py`)의 표준 소비 인터페이스
호스트 백엔드는 이 표준 객체를 받아 단 1줄의 함수로 파일 저장과 실시간 브로드캐스팅을 끝낸다:

```python
class LlmTracer:
    def ingest_pipeline_telemetry(self, telemetry: PipelineTelemetry) -> None:
        """
        1. telemetry.spans 를 apps/api/data/runs/{run_id}/ledger.jsonl 에 Append.
        2. telemetry.snapshots 를 apps/api/data/runs/{run_id}/snapshots.json 에 영속화.
        3. 실시간 구독 중인 WebSocket / SSE 연결로 이벤트 브로드캐스트.
        """
        ...
```

## 5. 인터페이스 4: 백엔드 ↔ 프론트엔드 실시간 통신 인터페이스 (SSE Protocol)

프론트엔드 Inspector UI가 백엔드 파이프라인의 실시간 실행 상태를 수신하는 HTTP SSE(Server-Sent Events) 규약이다.

### 5.1 엔드포인트 규격
* **URL**: `GET /api/v1/inspector/runs/{run_id}/events`
* **Content-Type**: `text/event-stream`
* **인증**: Bearer 토큰 (또는 로컬 개발자 세션)

### 5.2 이벤트 스트림 프로토콜 명세

```text
event: span_start
data: {"span_id": "01j7x...", "dotted_order": "...", "name": "build_context", "span_type": "tool"}

event: llm_chunk
data: {"span_id": "01j7y...", "delta": "{\"sections\": [", "index": 0}

event: model_attempt_failed
data: {"span_id": "01j7y...", "attempt_index": 1, "provider": "agy_cli", "reason": "timeout"}

event: model_attempt_start
data: {"span_id": "01j7y...", "attempt_index": 2, "provider": "google_api"}

event: state_checkpoint
data: {"stage_id": "context_build", "stage_name": "문서 컨텍스트 빌드", "payload": {...}}

event: span_end
data: {"span_id": "01j7y...", "status": "success", "latency_ms": 1840.0, "tokens": {...}}
```

## 6. 실전 리팩토링 Before & After (코드 적용 가이드)

### Before (기존의 수동 딕셔너리 하드코딩 방식)
```python
# outline/pipeline.py
ctx_started_at = _utc_now_iso()
t0 = time.time()
doc_ctx = self.context_builder.build_context(pdf_path)
ctx_duration = round(time.time() - t0, 3)
ctx_ended_at = _utc_now_iso()

# 수십 줄 뒤에 손으로 수동 작성...
steps = [
    {
        "name": "DocumentContextBuilder",
        "run_type": "tool",
        "start_time": ctx_started_at,
        "end_time": ctx_ended_at,
        "duration_seconds": ctx_duration,
        "inputs": {"filename": pdf_path.name},
        "outputs": {"context_chars": len(doc_ctx["context_text"])},
        "status": "SUCCESS",
    }
]
```

### After (표준 인터페이스 적용 후)
```python
# outline/pipeline.py
collector = StepCollector(pipeline_name="OutlinePipeline")

with collector.step("DocumentContextBuilder", span_type=SpanType.TOOL) as step:
    doc_ctx = self.context_builder.build_context(pdf_path)
    step.set_inputs({"filename": pdf_path.name})
    step.set_outputs({"context_chars": len(doc_ctx["context_text"])})
    # PDF 시각 검증용 도메인 스냅샷 캡처
    step.snapshot("context_build", "문서 컨텍스트 빌드", doc_ctx)

with collector.step(f"LLM:{actual_model}", span_type=SpanType.LLM) as step:
    exec_res = self.harness.run_structured(prompt, self.schema_path)
    # attempts(1차, 2차...)와 토큰 통계가 자동으로 스팬에 바인딩됨
    step.attach_harness_result(exec_res)

# 최종 텔레메트리 객체 방출 (P1 헌법 100% 준수)
telemetry = collector.export_telemetry(provenance=...)
```

## 7. 향후 추가 엔진 및 어댑터 확장 체크리스트

새로운 엔진이나 LLM 어댑터를 개발할 때는 다음 인터페이스 계약만 확인하면 된다:

- [ ] **새 엔진 생성 시**:
  - `packages/agent-telemetry`를 `pyproject.toml`에 추가.
  - 파이프라인 주요 단계를 `with collector.step():`으로 감싸기.
  - 반환값에 `collector.export_telemetry()`를 실어서 방출.
- [ ] **새 LLM 어댑터(`claude-cli`, `hermes` 등) 추가 시**:
  - `BaseLlmHarness`를 상속받아 `_execute_single_attempt` 1개 메서드만 구현.
  - `execution_protocol` 프로퍼티 지정 (`CLI_SUBPROCESS` or `LOCAL_SERVING`).
  - Fallback 및 Attempt 로깅은 부모 클래스가 자동으로 처리.
