# 에디터 워크스페이스 코어 프레임워크 스택 후보군

## 1. 개요 및 지향점
- **Antigravity IDE (VS Code 기반):** 멀티 패널 도킹, 탭 분할(Split View), 축소/확장, 고밀도 엔지니어링 셸 환경.
- **스크리브너 (Scrivener):** 무한 뎁스 바인더(Binder) 트리, 아웃라이너(계층/호이스팅), 코르크보드(인덱스 카드 그리드), 스크리브닝(청크 연속 편집), 인스펙터(메타데이터/참조).
- **목적:** 대규모·장문 문서의 구조적 분할·조립과 시각적 스캐폴딩 매핑을 지원하는 에디터 페이지의 기초 라이브러리 및 패키지 뼈대 확정.

---

## 2. 영역별 코어 패키지 후보군

### 2.1 셸 & 워크스페이스 도킹 레이아웃 (IDE 감성)
- **`dockview` (`dockview-react`) — (1순위 추천)**
  - **역할:** VS Code 레이아웃 엔진 벤치마킹 도킹 매니저.
  - **선정 이유:** 중앙 에디터의 무한 상하/좌우 분할(Split Editor), 탭 드래그 앤 드롭 이동, 사이드/하단 패널 도킹 및 접기/펼치기 네이티브 지원.
  - **대안 비교:** `react-resizable-panels`는 가볍고 단순 3단 레이아웃에 적합하나, 탭 분할 및 유연한 창 도킹이 불가능해 IDE 감성 확장에 제약이 있음.

### 2.2 바인더 & 아웃라이너 (스크리브너 바인더 감성)
- **`react-arborist` — (1순위 추천)**
  - **역할:** 가상 스크롤(Virtualization) 내장 고성능 React 트리 뷰.
  - **선정 이유:** 수백 개 이상의 문서 청크/섹션 노드를 버벅임 없이 렌더링하며, 키보드 네비게이션, 인라인 이름 변경, 다중 선택, 노드 간 드래그 앤 드롭(위계/순서 재편) 완벽 지원.
  - **주요 기능 매핑:** 스크리브너의 바인더 트리 및 아웃라이너 호이스팅(특정 노드 더블클릭 시 해당 서브트리 집중 모드).

### 2.3 코어 본문 에디터 (리치 텍스트 & 연속 문서 편집)
- **`@tiptap/react` + ProseMirror 생태계 — (프로젝트 확정 표준)**
  - **역할:** 헤드리스 위지윅 / 마크다운 문서 편집 엔진.
  - **핵심 패키지 조합:**
    - `@tiptap/react`, `@tiptap/starter-kit`: 기본 텍스트 서식 및 블록 제어.
    - `tiptap-markdown`: 내부 JSON 모델과 마크다운(`.md`) 파일 간의 양방향 무손실 변환.
    - `@tiptap/extension-mention`: 문서 간 양방향 링크(위키링크 `[[...]]`) 및 에셋 카드 멘션.
  - **스크리브너 기능 매핑:** 단일 노드 집중 편집(Hoisting) 및 다중 노드 묶음 연속 편집(Scrivenings View).

### 2.4 코르크보드 & 스캐폴드 매핑 (스크리브너 코르크보드 + 캔버스)
- **`@xyflow/react` (React Flow) — (프로젝트 확정 표준)**
  - **역할:** 2D 무한 캔버스 다이어그램 엔진.
  - **활용:** 스캐폴드 노드 매핑, 문서 지식 그래프, 에셋-문서 간 관계 시각화.
- **`@dnd-kit/core` + `@dnd-kit/sortable` — (코르크보드 및 드래그 소스)**
  - **역할:** 모던 헤드리스 드래그 앤 드롭 툴킷.
  - **활용:** 스크리브너 코르크보드(인덱스 카드 그리드 정렬 및 순서 재배치), 리소스 매니저 패널의 에셋 카드를 아웃라이너 노드나 에디터 본문으로 드롭(Drop)하는 인터랙션 처리.

### 2.5 인스펙터 & 문맥 제어 UI
- **`@floating-ui/react`:** 텍스트 선택 영역 또는 노드 좌표를 추적해 정밀하게 띄우는 문맥 플로팅 툴바(버블 메뉴).
- **Radix UI Primitives / shadcn/ui 기반 컴포넌트:** 우측 인스펙터의 메타데이터 필드, 시놉시스 메모, 아코디언, 탭 제어.

### 2.6 클라이언트 상태 관리
- **`zustand` — (프로젝트 확정 표준)**
  - 활성 탭/분할 뷰포트 상태, 포커스된 청크 노드 ID, 뷰 모드(에디터 / 코르크보드 / 캔버스) 동기화.

## 4. 검토 및 구현 가이드라인
1. **FSD 레이어 및 경계 준수:**
   - 뷰포트/도킹 셸은 `widgets/editor-workspace`로 합성.
   - 바인더 트리는 `entities/document-chunk` 또는 `features/document-outliner`로 격리.
   - 패널 간 통신 및 상태는 JSX 내부가 아닌 `model/use*` 훅과 zustand 스토어로 제어.
2. **도메인 중립성 유지:**
   - 범용 문서 빌더/스캐폴딩 엔진에 맞추어 모든 데이터 모델은 특정 콘텐츠 장르에 종속되지 않는 `Document`, `Section`, `Chunk`, `Asset`, `Scaffold` 규격을 사용.
