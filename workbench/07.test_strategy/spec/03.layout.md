## 1. 규칙 세 줄

1. **테스트는 검증 대상과 같은 워크스페이스에 산다.**
2. **파일은 검증 대상 모듈당 하나.** 등급은 파일이 아니라 **마커**로 표시한다.
3. **새 회귀는 새 파일을 만들지 않는다.** 대상의 파일에 붙인다.

---

## 2. 워크스페이스 소유권

| 검증 대상 | 테스트 위치 |
| --- | --- |
| `packages/scaffold-engine/**` | `packages/scaffold-engine/tests/` |
| `packages/agent-core/**` | `packages/agent-core/tests/` |
| `packages/agent-telemetry/**` | `packages/agent-telemetry/tests/` |
| `apps/api/app/**`, `apps/api/main.py` | `apps/api/tests/` |

> **왜**: 엔진 계약이 깨졌는데 신호가 앱에서 오면, 원인이 어느 층인지 매번 다시 판단해야
> 한다. 2026-09-14 기준 `test_scaffold_multipage.py`(엔진 파이프라인),
> `test_llm_fallback.py`(llm_driver)가 `apps/api` 에 살고 있다 — 이행 대상이다.

### 애매한 경우의 판정

| 상황 | 소유 |
| --- | --- |
| 앱 어댑터가 엔진을 호출한다 | **앱** (어댑터가 검증 대상) |
| 엔진 파이프라인 자체의 결과 | **패키지** |
| 앱이 패키지 계약을 만족하는지 | **앱** (앱이 계약 소비자) |
| 패키지 계약 자체의 무손실성 | **패키지** |

> 기준: **"고장 나면 누가 고쳐야 하는가"** 쪽이 소유한다.

## 3. 파일 명명

```text
test_<검증 대상 모듈>.py
```

| 대상 | 파일 |
| --- | --- |
| `app/core/observation/run_store.py` | `test_run_observation_store.py` |
| `app/inspector/service.py` | `test_inspector_service.py` |
| `app/inspector/adapters/local_source_archive.py` | `test_source_archive.py` |
| 라우터 + 컨테이너 배선 (도메인 묶음) | `test_wiring_<domain>.py` |

**등급을 파일 이름에 넣지 않는다.** `test_L2_foo.py` 같은 이름은 등급이 바뀔 때 파일을
옮기게 만든다. 등급은 마커, 위치는 대상.

---

## 4. conftest 계층

```text
apps/api/tests/conftest.py            워크스페이스 공용 — 저장소 격리 + 픽스처 3종
packages/<pkg>/tests/conftest.py      패키지 공용 (필요할 때만)
```

| 층 | 소유하는 것 | 예 |
| --- | --- | --- |
| 워크스페이스 | 저장소 격리, `storage`, `container`, `api_client` | [`templates/conftest.workspace.py`](../templates/conftest.workspace.py) |
| 도메인별 (선택) | 그 도메인만 쓰는 픽스처 | `observability_runs` |

**하위 conftest 를 3층 이상 만들지 않는다.** 픽스처 해석 경로가 깊어지면
"이 픽스처가 어디서 왔는가"를 추적하는 비용이 테스트를 읽는 비용을 넘는다.

## 5. 커버리지 체크리스트 (숫자 대신 이것을 센다)

새 코드를 추가할 때:

### 포트를 추가했다
- [ ] 구현 어댑터마다 **L2** 하나 — 정상 경로
- [ ] 부재·손상 응답 **L2** 하나
- [ ] 과행동 방어 **L2** 하나 (삭제·갱신이면 필수)
- [ ] 식별자로 경로를 만든다면 **탈출 거부 L2** 하나

### 라우터 엔드포인트를 추가했다
- [ ] **L3** 하나 — 상태 코드 + 주입 경로
- [ ] 오류 번역이 있다면 **L3** 하나 — 도메인 오류 → HTTP 코드

### 계약(모델·어휘)을 추가했다
- [ ] **L1** 하나 — 왕복 검증
- [ ] 선택 필드가 있다면 **L1** 하나 — 누락 시 동작

### 부팅이 하는 일을 추가했다
- [ ] **L3** 하나 — 그 일이 실제로 일어났는가
- [ ] 순서 의존이 있다면 순서까지 단언

### 새 도메인을 만들었다
- [ ] `import-linter` 계약 추가 (**L0**)
- [ ] `test_architecture_contracts.py` 가 자동으로 검증하므로 별도 테스트 불필요

## 6. 파일이 커지면

한 파일의 테스트가 **15개를 넘으면** 검증 대상이 둘 이상 섞였는지 본다.

| 원인 | 조치 |
| --- | --- |
| 대상 모듈이 여러 관심사를 갖는다 | **구현을 먼저 쪼갠다.** 테스트는 따라온다 |
| 한 대상에 사고가 많이 쌓였다 | 그대로 둔다. **사고 기록은 자산이다** |
| 등급이 섞였다 | 마커로 구분하고, 그래도 크면 대상별로 분리 |

> 2026-09-14 기준 `test_inspector.py` 는 18개다. 원인은 첫 번째였다 —
> 조회·소스 조회·워크플로우 카탈로그가 한 서비스에 있었다. 구현을 쪼개자 테스트도 갈렸다.
