## 1. 현재 상태

**저장소 어디에도 `[tool.pytest.ini_options]` 가 없다.**

```bash
grep -rn "tool.pytest" apps packages    # (결과 없음)
```

pytest 는 `pyproject.toml` 을 rootdir 앵커로만 쓰고 있다. 그래서:

| 없는 것 | 결과 |
| --- | --- |
| `testpaths` | 경로를 매번 손으로 |
| **`markers`** | **부분 실행 불가** — 이것이 "매번 전체를 돌린다"의 직접 원인 |
| `addopts` | 옵션을 매번 손으로 |
| `filterwarnings` | 경고가 계속 쌓임 |

## 2. `apps/api/pyproject.toml`

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-ra --strict-markers -m 'not wiring'"
markers = [
    "wiring: 앱을 부팅하는 L3 배선 테스트 (pnpm test:all 에서만 실행)",
    "external: 외부 프로세스를 실제로 띄우는 테스트",
]
filterwarnings = [
    "error::DeprecationWarning:app.*",
    "error::DeprecationWarning:agent_core.*",
    "error::DeprecationWarning:agent_telemetry.*",
    "error::DeprecationWarning:scaffold_engine.*",
]
```

### 옵션별 근거

| 옵션 | 왜 이 값인가 |
| --- | --- |
| `testpaths = ["tests"]` | `pytest` 만 쳐도 같은 것이 돈다. 경로 실수로 다른 범위를 도는 일이 없다 |
| `-ra` | 통과 외 결과(스킵·xfail·에러)를 끝에 요약. **조용히 사라지는 것을 막는다** |
| `--strict-markers` | 오타 난 마커를 **에러**로. 없으면 `wirring` 으로 잘못 쓴 L3 가 조용히 기본 실행에 섞인다 |
| `-m 'not wiring'` | **기본은 L1+L2.** L3 는 `pnpm test:all` 에서만 |
| `markers` | 마커를 선언하지 않으면 `--strict-markers` 가 전부 거부한다 |
| `filterwarnings` | **우리 코드의** Deprecation 만 에러로. 서드파티까지 올리면 라이브러리 업그레이드마다 스위트가 멈추고, 그러면 아무도 이 설정을 신뢰하지 않게 된다 |

### `-m 'not wiring'` 을 기본에 두는 이유

기본 실행이 **매 저장마다 부담 없이 돌 수 있어야** 게이트에 넣을 수 있다.
L3 는 앱 부팅(1.6초)이 필수라 기본에 두면 예산을 초과한다.

`pnpm test:all` 은 `-m ""` 로 필터를 덮어쓴다.

## 4. 비동기 스타일

현재 두 가지가 섞여 있다.

| 스타일 | 파일 |
| --- | --- |
| `@pytest.mark.anyio` | `test_outline_observability.py`, `test_scaffold_observability.py` |
| `asyncio.run()` | `test_run_recovery.py`, `test_llm_runtime_policy.py` |

**새 테스트는 `@pytest.mark.anyio` 로 통일한다.**

예외: 백그라운드 태스크를 여러 번 돌려야 하는 시나리오
(`await asyncio.sleep(0)` 를 반복해 `create_task` 가 한 바퀴 돌게 하는 경우)는
`asyncio.run()` 이 읽기 쉬울 수 있다. **그런 경우 왜 그 스타일인지 주석으로 남긴다.**

```python
async def scenario() -> None:
    await service.decide_agreement(agreement_id, approved=True)
    await asyncio.sleep(0)      # 백그라운드 태스크가 한 바퀴 돌 기회를 준다
    await asyncio.sleep(0)

asyncio.run(scenario())
```

## 5. basetemp 와 캐시

```bash
venv/Scripts/python.exe -m pytest --basetemp .pytest_tmp/basetemp
```

| 경로 | 용도 | gitignore |
| --- | --- | --- |
| `.pytest_tmp/storage-<pid>/` | 등급 루트 격리 (conftest) | ✅ (`**/.pytest_tmp/`) |
| `.pytest_tmp/basetemp/` | `tmp_path` 픽스처 | ✅ |
| `.pytest_cache/` | pytest 자체 캐시 | ✅ |

**시스템 임시 디렉터리를 쓰지 않는다.** 샌드박스·권한 정책이 다른 환경에서 접근이 거부될
수 있고, 실제로 그 문제를 겪었다. 저장소 안의 gitignore 된 경로가 예측 가능하다.

## 6. 확인 절차

```bash
# 설정이 잡혔는가 — configfile 줄에 pyproject.toml 이 보여야 한다
cd apps/api && venv/Scripts/python.exe -m pytest --collect-only -q | head -5

# 마커 필터가 동작하는가 — 두 수가 달라야 한다
venv/Scripts/python.exe -m pytest --collect-only -q | tail -1
venv/Scripts/python.exe -m pytest -m "" --collect-only -q | tail -1

# 오타 마커가 차단되는가
venv/Scripts/python.exe -m pytest -m "wirring"     # 에러가 나야 정상
```
