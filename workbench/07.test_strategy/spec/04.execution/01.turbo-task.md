## 1. 현재 상태

```json
// turbo.json — 2026-09-14
{ "tasks": { "build": {...}, "typecheck": {...}, "lint": {}, "dev": {...} } }
```

`test` 태스크가 없다. **`turbo run test` 를 실행할 방법이 없다.**

`packages/*` 테스트 14개는 어떤 명령으로도 자동 실행되지 않는다.

## 2. 태스크 정의

```json
{
  "tasks": {
    "test": {
      "dependsOn": [],
      "inputs": [
        "app/**/*.py",
        "tests/**",
        "migrations/**/*.py",
        "main.py",
        "pyproject.toml",
        "requirements*.txt"
      ],
      "outputs": [],
      "env": ["VIBE_CONFIG_DIR", "VIBE_DATA_DIR", "VIBE_CACHE_DIR", "VIBE_STATE_DIR"]
    },
    "test:all": { "...test 와 동일..." }
  }
}
```

### 각 필드의 근거

| 필드 | 값 | 왜 |
| --- | --- | --- |
| `dependsOn` | `[]` | Python 워크스페이스는 소스를 직접 임포트한다. `^build` 를 걸면 불필요한 의존이 캐시 적중률만 떨어뜨린다 |
| `inputs` | 명시 | **지정하지 않으면 워크스페이스 전체를 해시한다.** README 한 줄만 고쳐도 테스트가 다시 돈다 — 캐시가 있으나 마나가 된다 |
| `outputs` | `[]` | 테스트는 산출물이 없다. 종료 코드와 로그만 캐시된다. `.pytest_tmp` 는 출력이 아니라 쓰레기다 |
| `env` | 등급 루트 4개 | 이 변수가 바뀌면 **다른 저장소를 보게 된다.** 해시에 넣지 않으면 "환경이 달라졌는데 캐시 적중" 사고가 난다 |

### `inputs` 를 좁히는 것과 넓히는 것의 위험

| | 위험 |
| --- | --- |
| 너무 넓다 (기본값) | 문서 수정에도 테스트가 다시 돈다 → 캐시 무의미 |
| **너무 좁다** | 바뀐 것을 놓치고 **초록 거짓말**을 한다 |

> 위 목록은 "이것이 바뀌면 결과가 바뀔 수 있는 것" 전부다.
> 새 소스 디렉터리를 만들면 **여기에 추가하는 것을 잊지 않는다.**

## 3. 워크스페이스 스크립트

### `apps/api/package.json`

```json
{
  "scripts": {
    "test": "venv\\Scripts\\python.exe -m pytest --basetemp .pytest_tmp/basetemp",
    "test:all": "venv\\Scripts\\python.exe -m pytest -m \"\" --basetemp .pytest_tmp/basetemp"
  }
}
```

- `test` — `pyproject` 의 `addopts` 가 `-m 'not wiring'` 이므로 기본이 **L1+L2**.
- `test:all` — `-m ""` 로 마커 필터를 비워 **L3 포함**.
- `basetemp` — 격리 저장소와 같은 `.pytest_tmp` 아래로 모은다 (이미 gitignore 대상).

### `packages/*/package.json` — **신설 대상**

현재 `scaffold-engine`, `agent-core`, `agent-telemetry` 에는 `package.json` 이 없다.

```json
{
  "name": "@vibe/scaffold-engine",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "test": "../../apps/api/venv/Scripts/python.exe -m pytest"
  }
}
```

> **인터프리터를 늘리지 않는다.** 이 저장소는 `apps/api` 의 venv 하나로 모노레포 전체
> Python 을 돌린다 (`main.py` 가 `sys.path` 에 `packages` 를 넣는 방식과 같은 전제).
> 패키지별 venv 를 만들면 "어느 venv 에서 통과했는가"가 새 변수로 생긴다.

### 루트 `package.json`

```json
{
  "scripts": {
    "test": "turbo run test",
    "test:all": "turbo run test:all"
  }
}
```

## 4. 확인 절차

```bash
# 1. 태스크가 잡히는가
pnpm turbo run test --dry-run

# 2. 실제 실행
pnpm test

# 3. 캐시가 걸리는가 — 두 번째는 FULL TURBO 여야 한다
pnpm test && pnpm test

# 4. 변경 감지가 되는가 — 소스를 고치면 그 워크스페이스만 다시 돈다
touch packages/scaffold-engine/scaffold_engine/__init__.py && pnpm test
```

`pnpm-workspace.yaml` 에 `packages/*` 가 포함돼 있어야 turbo 가 새 워크스페이스를 본다.
포함돼 있지 않으면 스크립트를 만들어도 `turbo run test` 대상에 잡히지 않는다.
