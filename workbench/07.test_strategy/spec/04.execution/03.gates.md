## 2. 개정안

```diff
- pnpm lint && pnpm typecheck && pnpm build
+ pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

| 명령 | 무엇을 보장 | 예산 |
| --- | --- | ---: |
| `pnpm lint` | 경계(L0) · 스타일 | ~2초 |
| `pnpm typecheck` | 타입 | ~2초 |
| **`pnpm test`** | **계약(L1) · 행동(L2)** | ~3초 |
| `pnpm build` | 빌드 가능성 | ~2초 |

**커밋 전 추가**:

```bash
pnpm test:all      # + 배선(L3)
```

### 왜 `test` 가 `build` 앞인가

빌드는 가장 비싸고 가장 늦게 깨진다. 계약·행동이 깨진 코드를 빌드까지 끌고 갈 이유가 없다.
**싼 신호부터 받는다.**

### 왜 기본 게이트에 L3 를 넣지 않는가

L3 는 앱 부팅(1.6초)이 필수다. 매 저장마다 돌면 부담이 되고, 부담이 되면 사람이
게이트를 건너뛴다. **건너뛰는 게이트는 게이트가 아니다.**

## 3. 동작 확인은 여전히 별개다

```text
빌드 통과 ≠ 동작 확인
테스트 통과 ≠ 동작 확인
```

`00-core/rule.md` 의 원칙은 그대로다. 동작을 바꿨다면 **실제로 실행해서 확인**한다.

| 무엇을 바꿨나 | 확인 방법 |
| --- | --- |
| 엔드포인트 | 실제 호출해 응답·상태 코드 확인 |
| 부팅 시퀀스 | 서버를 띄워 로그 확인 |
| 저장 레이아웃 | `pnpm -F @vibe/api migrate:status` |

> L3 테스트가 있어도 이 확인을 대체하지 않는다. L3 는 **조립**을 보고,
> 실행 확인은 **실제 환경**을 본다.

## 4. 실패 진단 순서

실패한 **등급**이 원인 범위를 좁혀 준다.

```text
L0 만 빨강      → 경계 위반. 코드 위치나 import 방향이 틀렸다
L1 만 빨강      → 계약/어휘가 바뀌었다. 소비자를 전부 찾아야 한다
L2 만 빨강      → 행동이 바뀌었다. 그 포트 하나만 보면 된다
L3 만 빨강      → 조립이 틀렸다. 컨테이너/부팅 순서를 본다
L2+L3 빨강     → 행동 변경이 배선까지 전파. L2 부터 고친다
전부 빨강       → 공통 기반(픽스처·설정·환경)을 의심한다
```

### 자주 나오는 조합

| 증상 | 원인 후보 | 확인 |
| --- | --- | --- |
| 어제는 통과, 오늘 실패, 코드 무변경 | **저장소 오염** | `git status` 가 더러운가 / `data/runs` 수가 늘었는가 |
| 한 파일만 돌리면 통과, 전체는 실패 | 전역 상태 공유 | 전역 `TestClient`, 모듈 전역 변수, `settings` 변조 |
| 첫 실행만 실패 | 부팅 순서 / 빈 저장소 경로 | `.pytest_tmp` 지우고 재현 |
| CI 없이 로컬만 통과 | 환경 변수 · venv 차이 | `turbo` 의 `env` 필드 확인 |

## 5. 실패를 끄지 않는다

```python
# ✗ 이유 없는 skip
@pytest.mark.skip(reason="나중에 고침")

# ✗ 조건 없는 xfail
@pytest.mark.xfail
```

끌 수밖에 없다면 **끄는 이유와 조건**을 남긴다.

```python
@pytest.mark.skipif(
    sys.platform != "win32",
    reason="agy CLI 는 Windows 경로 규칙에 의존한다",
)
```

> 이유 없는 `skip` 은 **지워진 테스트와 같다.** 다만 지워진 사실이 보이지 않아 더 나쁘다.

## 6. CI 가 없다는 사실

2026-09-14 기준 `.github/` 가 없다. 게이트는 **사람이 로컬에서** 돌린다.

이 상태에서 가장 중요한 것은 **게이트가 싸야 한다는 것**이다. 비싸면 건너뛰고,
건너뛰면 없는 것과 같다. `pnpm test` 를 3초 예산으로 두는 이유가 이것이다.

CI 도입이 필요해지는 조건:

- 기여자가 둘 이상이 된다
- 게이트를 건너뛴 커밋이 실제로 발생한다
- 플랫폼 차이(Windows/Linux)가 문제가 되기 시작한다

> 지금은 해당 없음. **필요해지기 전에 만들지 않는다.**
