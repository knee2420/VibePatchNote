# 관측 픽스처 — 실제 산출물만 쓴다

- **문서 ID**: `TEST-SPEC-OBS-FIXTURES`
- **상태**: `Active`
- **최종 개정**: 2026-09-14
- **대상**: `apps/api/tests/fixtures/observability/`

---

## 1. 원칙

> **픽스처는 실제 생산자가 쓴 파일이어야 한다.**

손으로 지은 샘플은 생산자가 쓰지 않는 키를 담게 되고, 그러면 테스트가 통과하면서도
실제 데이터에서는 깨진다.

실제 사례: 손으로 만든 샘플이 `status: "SUCCESS"`(대문자)와 `duration_ms` 를 담고 있었다.
생산자는 소문자 `status` 와 다른 키를 쓴다. 테스트는 초록이었고, 화면은 비어 있었다.

---

## 2. 구조

```text
apps/api/tests/fixtures/observability/
├── README.md              각 run 이 대표하는 상황
├── _build_fixtures.py     생성기 (실제 data/ 에서 복사 + 축약)
├── runs/
│   ├── run-1a094630557-4e4f96ee/      완전한 run (meta·ledger·snapshots·events)
│   ├── run-contract-20260911-191719/  attempt 기록이 있는 run
│   └── agent-5a0846d55d53/            events 만 있는 run (계측 없음)
└── ledger/                월별 비용 원장
```

각 run 이 **서로 다른 상황**을 대표한다. 이것이 픽스처 3개로 18개 테스트를 지탱하는 이유다.

| run | 대표하는 상황 |
| --- | --- |
| `run-1a09...` | 정상 — 계측·원장·스냅샷 전부 있음 |
| `run-contract-...` | 재시도(attempt)가 기록된 실행 |
| `agent-5a08...` | **계측이 없는 실행** — 목록에서 사라지면 안 되는 경우 |

> 세 번째가 중요하다. 예전에는 `meta.json` 있는 디렉터리만 목록에 올려서
> **54건 중 37건이 화면에서 사라졌다.** 그중에는 TIMEOUT 과 FAILED 도 있었다.

---

## 3. 갱신 절차

저장 레이아웃이나 계측 스키마가 바뀌면 픽스처도 갱신한다.

```bash
cd apps/api/tests/fixtures/observability
python _build_fixtures.py --source ../../../data
```

생성기가 하는 일:

1. 실제 `data/runs` 에서 지정된 run 디렉터리를 복사한다.
2. **긴 문자열 값만** 자른다 (300자 초과 → 200자).
3. **키 이름·대소문자·구조·숫자는 건드리지 않는다.**

> 2·3 이 핵심이다. 커밋 가능한 크기로 만들되 **생산자의 어휘를 보존**한다.

### 갱신 후 확인

```bash
cd apps/api && venv/Scripts/python.exe -m pytest tests -k "inspector or observability" -q
```

깨지면 **픽스처가 아니라 코드를 본다.** 픽스처는 실제 산출물이므로, 깨졌다는 것은
소비자가 새 형식을 못 읽는다는 뜻이다.

## 4. 픽스처를 손으로 고치지 않는다

```bash
# ✗ 테스트를 통과시키려고 픽스처 JSON 을 편집
vim tests/fixtures/observability/runs/run-1a09.../meta.json
```

이 순간 픽스처는 "실제 산출물"이 아니게 되고, 원칙이 무너진다.
형식이 바뀌었다면 **생성기를 다시 돌린다.**

예외: 개인정보·경로가 섞인 경우. 이때는 생성기에 마스킹 규칙을 추가하고
**생성기를 통해** 다시 만든다.

## 5. 픽스처를 저장소에 까는 방법

```python
@pytest.fixture
def observability_runs() -> list[str]:
    """실제 생산자가 쓴 run 디렉터리를 저장소에 깔고, 끝나면 치운다."""
    runs_dir = settings.storage.runs          # ← 격리된 임시 저장소를 가리킨다
    ...
```

`settings.storage.runs` 를 쓰지만, conftest 의 저장소 격리 덕분에 이것은
**임시 디렉터리**다. 격리가 없으면 이 픽스처가 개발 PC 의 실제 `data/` 를 오염시킨다.
→ [`examples/92.antipattern-real-data.md`](../../examples/92.antipattern-real-data.md)

## 6. 새 픽스처가 필요할 때

새 run 을 추가하기 전에 묻는다.

| 질문 | 아니오라면 |
| --- | --- |
| 기존 3개가 대표하지 못하는 **새로운 상황**인가? | 기존 것을 쓴다 |
| 실제로 생산된 적 있는 형태인가? | **만들지 않는다.** 존재하지 않는 상황을 검증하게 된다 |
| 축약 후에도 그 상황을 대표하는가? | 축약 규칙을 조정한다 |

그리고 `fixtures/observability/README.md` 에 **이 run 이 대표하는 상황**을 한 줄 남긴다.
없으면 다음 사람이 지워도 되는지 판단할 수 없다.
