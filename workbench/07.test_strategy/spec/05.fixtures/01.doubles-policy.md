- **문서 ID**: `TEST-SPEC-DOUBLES`

---

## 1. 판정 규칙 한 줄

> **대역은 외부 경계에서만 쓴다.** 저장소 안의 객체는 실물을 쓴다.

"외부"의 정의는 셋뿐이다.

1. **다른 프로세스** — `agy` CLI 서브프로세스
2. **네트워크** — Google REST API
3. **OS 자원** — 키링, 사용자 홈의 설정 파일

나머지는 전부 내부다. 파일 I/O 는 `tmp_path` 로 격리되므로 외부가 아니다.

## 2. 판정표

| 협력자 | 판정 | 이유 |
| --- | :---: | --- |
| `AgentRuntime` + `LocalAgentRunRepository` | **실물** | 순수 로컬·빠름. 대역을 쓰면 이벤트 폴드가 검증 안 됨 |
| `LocalLedger` | **실물** | 동일 |
| `ApprovalService` | **실물** | 동일 |
| 문서/스캐폴드 저장소 어댑터 | **실물**(`tmp_path`) | 파일 레이아웃이 검증 대상의 일부 |
| `RunObservationStore` | **실물**(`tmp_path`) | 동일 |
| `StorageRoots` | **실물**(`storage` 픽스처) | 동일 |
| **LLM 하네스** | **대역** | 외부 프로세스·네트워크 |
| **OS 키링** (`OsCredentialStore`) | **대역** | 개발 PC 의 실제 자격 증명을 건드림 |
| **`~/.gemini` 설정 파일** | **대역** | 사용자 홈을 건드림 |
| 다른 도메인의 서비스 | **대역**(포트 구현) | 그 도메인의 행동은 그쪽 테스트가 본다 |
| `Container` 전체 | **실물 + 부분 override** | 조립 자체가 검증 대상 |

## 3. 실물을 쓰는 이유 — 실제 사례

```python
def _runtime(tmp_path: Path):
    """실제 Agent Runtime. 대역이 아니라 본 물건을 쓴다.

    유스케이스의 협력자가 전부 필수가 된 뒤로, 런타임 없이 만든 유스케이스는
    프로덕션에 존재하지 않는 조합이 되었다. 그런 조합을 테스트가 만들어 내면
    테스트는 자기가 지어낸 세계를 검증한다.
    """
    from agent_runtime import AgentRuntime, LocalAgentRunRepository, LocalLedger

    return AgentRuntime(
        runs=LocalAgentRunRepository(tmp_path / "runs"),
        ledger=LocalLedger(tmp_path / "ledger"),
    )
```

`AgentRuntime` 을 대역으로 바꾸면 **이벤트 소싱 폴드가 검증되지 않는다.**
`record_cost` 가 원장에 쓰는지, 재개가 `attempt` 를 올리는지 — 전부 실물만 보여준다.

> **판정 기준**: 대역으로 바꿨을 때 **검증 대상의 일부가 함께 사라지는가?**
> 사라진다면 실물을 써야 한다.

## 4. 대역의 형태

### 최소 대역 — 필요한 메서드만

```python
class _StubHarness:
    """모델 이름만 묻는 자리. 실제 실행은 엔진 어댑터가 한다."""

    model = "test-model"
```

프로토콜 전체를 구현하지 않는다. **이 테스트가 실제로 부르는 것만** 둔다.
전부 구현하면 "무엇이 쓰이는가"가 코드에서 사라진다.

### 호출을 거부하는 대역 — 안 불려야 하는 것

```python
class _CredentialStore:
    def get_google_api_key(self) -> str:
        return "AIza0123456789abcdefgh"

    def set_google_api_key(self, api_key: str) -> None:
        raise AssertionError(f"unexpected write: {api_key}")     # ← 쓰기는 사고다

    def delete_google_api_key(self) -> None:
        raise AssertionError("unexpected delete")
```

> **읽기만 하는 경로를 검증할 때, 쓰기 메서드는 예외를 던지게 둔다.**
> 조용히 통과시키면 "읽기만 한다"는 사실이 검증되지 않는다.

### 기록하는 대역 — 무엇이 호출됐는지 봐야 할 때

```python
class ExecutionLog:
    """구체 하네스가 실제로 받은 (공급자, 모델, 타임아웃)."""

    def __init__(self) -> None:
        self.calls: list[tuple[str, str, int]] = []
```

## 5. 대역을 어디에 두는가

| 범위 | 위치 |
| --- | --- |
| 한 파일에서만 쓴다 | 그 파일 상단 (`_StubHarness` 처럼 `_` 접두) |
| 두 파일 이상에서 쓴다 | `tests/doubles.py` 로 모은다 |
| 모든 L3 가 쓴다 | conftest 픽스처로 |

> 2026-09-14 기준 13개 대역 클래스가 7개 파일에 흩어져 있고 이름 규칙도 제각각이다
> (`FakeHarness`, `_StubHarness`, `_MockMultiPageHarness`, `_CredentialStore`).
> **이름은 `_Fake<역할>` 또는 `_Stub<역할>` 로 통일한다.**

| 접두 | 뜻 |
| --- | --- |
| `_Stub` | 값을 돌려주기만 한다 |
| `_Fake` | 단순화된 동작이 있다 (인메모리 저장소 등) |
| `Mock` | **쓰지 않는다.** `unittest.mock` 과 혼동된다 |

## 6. `monkeypatch` 를 쓰는 경우

객체 주입으로 막을 수 없을 때만 쓴다. **지점은 고정 목록에서만 고른다.**
→ [`02.external-boundaries.md`](./02.external-boundaries.md)

```python
# ✓ 외부 경계 — 목록에 있는 지점
monkeypatch.setattr("llm_driver.adapters.gemini.requests.post", fake_post)

# ✗ 내부 구현 — 리팩터링하면 조용히 무력화된다
monkeypatch.setattr("app.inspector.service.InspectorService._summarize", ...)

# ✗ 전역 설정 변조 — 프로세스 전역 상태를 테스트가 바꾼다
monkeypatch.setattr(settings, "agent_cli_model", "...")
#   → 주입된 RuntimeExecutionPolicy 를 쓴다
```

## 7. 하지 말 것

| 금지 | 대신 |
| --- | --- |
| 내부 메서드 `monkeypatch` | 포트를 대역으로 주입 |
| 프로토콜 전체를 구현한 대역 | 쓰이는 메서드만 |
| 쓰기 메서드를 조용히 통과 | `AssertionError` 로 거부 |
| `Mock` 접두 | `_Stub` / `_Fake` |
| 실물로 충분한데 대역 | 검증 대상이 사라지는지 먼저 확인 |
