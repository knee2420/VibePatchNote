## 이 등급이 지키는 가장 중요한 것 — 어휘

이 저장소에는 **어휘가 둘** 있다.

```text
공급자 어휘   prompt_tokens · completion_tokens · reasoning_tokens  · cache_read_tokens
제품 어휘     input_tokens  · output_tokens     · thinking_tokens   · cache_read_tokens
```

변환표의 정본은 `agent_telemetry/contracts/usage.py` 의 `_PRODUCT_TO_PROVIDER` 하나다.

그리고 **run 어휘와 스팬 어휘**도 다르다.

```text
스팬(SpanStatus)  success · failed · running · pending · skipped
run(RunStatus)    completed · failed · running · queued · waiting_for_*
```

> 어휘가 섞이면 **소비자가 양쪽을 모두 비교해야 하고, 한쪽만 맞추면 나머지가 전부
> 실패로 그려진다.** 실제로 목록에서 그런 일이 있었다.

L1 의 핵심 임무는 **변환 지점이 하나임을 강제**하는 것이다.

## 필수 3종

계약 테스트는 아래 셋을 갖춘다.

| 종류 | 무엇을 보는가 | 없으면 |
| --- | --- | --- |
| **왕복(round-trip)** | 변환 후 되돌려도 같은가 | 역방향에서 0 이 되는 필드를 놓친다 |
| **누락 필드** | 공급자가 안 준 값을 어떻게 다루는가 | "없음"과 "0"이 뒤섞인다 |
| **덮어쓰지 않음** | 공급자가 준 값을 우리가 재계산해 덮지 않는가 | 공급자만 아는 내부 토큰이 사라진다 |

실제 예: [`examples/01.L1-usage-vocabulary.md`](../../examples/01.L1-usage-vocabulary.md)

## 소유권

**계약이 사는 패키지가 테스트도 소유한다.**

| 계약 | 테스트 위치 |
| --- | --- |
| `agent_telemetry.contracts.*` | `packages/agent-telemetry/tests/` |
| `agent_core.runtime.models` | `packages/agent-core/tests/` |
| `scaffold_engine` 스키마 | `packages/scaffold-engine/tests/` |
| `app/<domain>/schemas.py` (HTTP 계약) | `apps/api/tests/` |

> 앱에서 패키지 계약을 검증하면, 계약이 깨졌을 때 **앱 테스트가 빨개진다.**
> 원인이 패키지에 있는데 신호는 앱에서 온다.
