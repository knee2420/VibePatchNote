## 왜 세션당 한 번만 부팅하는가

`import main` 은 **1.59초**다(2026-09-14 실측). 모듈마다 클라이언트를 만들면 그만큼
반복된다. `api_client` 를 세션 스코프로 두면 부팅 비용은 한 번이다.

```python
@pytest.fixture(scope="session")
def api_client():
    with TestClient(main.app) as client:      # with 가 lifespan 을 돌린다
        yield client
```

**`with` 가 핵심이다.** 없으면 lifespan 이 실행되지 않아 재개 등록·정책 복원·고아 정리가
전부 건너뛰어진다 — 프로덕션에 없는 상태.
→ [`examples/90.antipattern-global-client.md`](../../examples/90.antipattern-global-client.md)

## 무엇을 단언하는가

L3 는 **"연결"** 을 본다. **"계산"** 은 L2 가 이미 봤다.

| 본다 | 보지 않는다 |
| --- | --- |
| 상태 코드 | 응답 본문의 모든 필드 값 |
| 주입된 대역이 호출됐는가 | 그 대역이 만든 값이 옳은가 |
| 부팅 후 런타임 상태(등록 목록 등) | 등록된 핸들러의 동작 |
| 오류가 올바른 HTTP 코드로 번역되는가 | 그 오류의 발생 조건 |

```python
# ✓ L3 — 연결을 본다
def test_outline_failure_is_not_reported_as_http_success(api_client) -> None:
    with main.container.outline_service.override(providers.Object(FailedOutlineService())):
        response = api_client.post("/api/v1/outlines/extract", json={"docId": "doc-test"})

    assert response.status_code == 424                      # 번역이 맞는가
    assert response.json()["error"]["code"] == "FALLBACK_NOT_CONFIGURED"
```

```python
# ✗ L3 에서 계산을 본다 — L2 와 이중 검증
def test_outline_extracts_correct_headings(api_client):
    response = api_client.post("/api/v1/outlines/extract", json={"docId": "doc-1"})
    assert len(response.json()["outlines"]) == 4            # 이건 L2 의 일이다
```

## 목록은 전체를 단언한다

부팅 등록처럼 **"빠뜨림"이 사고의 모양**인 경우, `in` 이 아니라 `==` 를 쓴다.

```python
# ✓ 새 유스케이스를 추가하고 등록을 빠뜨리면 깨진다
assert registered == [
    "documents.extract_outline",
    "documents.generate_scaffold",
    "documents.scan_segments",
]

# ✗ 빠뜨림을 못 잡는다
assert "documents.extract_outline" in registered
```

실제 예: [`examples/03.L3-resume-flow.md`](../../examples/03.L3-resume-flow.md)

## 대역은 컨테이너로 끼운다

```python
with main.container.workspace_service.override(providers.Object(FakeWorkspaceService())):
    response = api_client.get("/api/v1/workspaces")
```

`monkeypatch` 로 모듈 속성을 바꾸지 않는다. **갈아끼우는 지점도 컨테이너 하나**여야
"실제로 무엇이 주입되는가"의 답이 한 곳에 남는다.

## 부팅 시퀀스 커버리지

lifespan 이 하는 일마다 L3 하나를 둔다. 2026-09-14 기준 `main.py` lifespan 은 넷을 한다.

| 단계 | 테스트 |
| --- | --- |
| 저장된 실행 정책 복원 | `test_saved_policy_is_restored_at_boot_not_on_first_settings_request` |
| 재개 핸들러 등록 | `test_every_resumable_use_case_is_registered_at_boot` |
| 끊긴 실행 정리 | `test_interrupted_runs_are_swept_on_boot` |
| 만료 로그 정리 | (미비 — 이행 대상) |

> **순서**도 검증 대상이다. 등록이 고아 정리보다 먼저여야 하고, 버전 확인이
> 디렉터리 생성보다 먼저여야 한다. 순서가 틀려 **새 설치가 부팅되지 않은 적이 있다.**
