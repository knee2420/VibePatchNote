## 판정

결정 표 **1번 질문에서 멈추는 것**들이다.

> **코드를 실행하지 않고 증명되는가?** → 예

| 대상 | L0 인가 | 이유 |
| --- | :---: | --- |
| `packages` 가 `app` 을 import 하는가 | ✅ | import 그래프는 정적 |
| 도메인이 다른 도메인을 import 하는가 | ✅ | 동일 |
| 서비스가 `app.core.config` 를 import 하는가 | ✅ | 동일 |
| 계약 목록이 실제 도메인과 일치하는가 | ✅ | 디렉터리 목록 vs TOML 파싱 |
| 어댑터가 저장 루트를 **주입받는가** | ❌ | 생성자 시그니처는 정적이지만, **행동**은 실행해야 안다 → L2 |
| 라우터가 주입된 서비스를 쓰는가 | ❌ | 실행해야 안다 → L3 |

## 현재 적용 중인 계약 (11건)

```bash
cd apps/api && venv/Scripts/lint-imports.exe
```

| 계약 | 지키는 것 |
| --- | --- |
| Core must not import domains | `core/` 는 도메인을 모른다 |
| Agent Core is domain agnostic | `agent_runtime`·`llm_driver` 는 비즈니스를 모른다 |
| Scaffold Engine is independent | 엔진은 런타임·호스트를 모른다 |
| Storage paths are known only to adapters and bootstrap | `app.*.service`/`use_cases`/`agents`/`experimental` 는 `app.core.config` 를 모른다 |
| `<domain>` must not depend on other domains × 7 | 도메인 간 직접 참조 금지 |

> **세그먼트 와일드카드가 핵심이다.** `app.*.service` 로 쓰면 새 도메인이 자동 포함된다.
> 도메인을 열거하면 목록에 없는 도메인이 규칙 밖에서 태어난다 —
> 실제로 `inspector` 가 그랬다.

## 예외 — 테스트로 남기는 메타 검사

`import-linter` 로 표현할 수 없는 것이 하나 있다: **계약 목록 자체가 낡았는지.**

```python
# apps/api/tests/test_architecture_contracts.py

def test_every_domain_has_an_independence_contract() -> None:
    """새 도메인은 규칙 밖에서 태어나지 않는다."""
    assert _independence_contracts().keys() == _domains_on_disk()
```

이것은 **규칙의 재구현이 아니라 규칙 목록의 검사**다. 경계가 분명하다.

| 구분 | 예 |
| --- | --- |
| ✅ 메타 검사 (테스트로 OK) | "계약이 7개 도메인을 전부 덮는가" |
| ❌ 규칙 재구현 (계약으로) | "도메인 A 가 B 를 import 하는가" |

> 이 검사들은 `lint` 단계로 옮기는 것이 이상적이다(T1). 옮기기 전까지는 테스트로 두되,
> **규칙 자체를 다시 짜지 않는다**는 선을 지킨다.
