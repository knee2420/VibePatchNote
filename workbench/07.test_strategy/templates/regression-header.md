# 사고 기록 주석 형식 (Regression Header)

> 이 저장소의 테스트는 **"무엇을 검사하는가"가 아니라 "무엇이 실제로 일어났는가"** 를 적는다.
> 그 주석이 없으면 6개월 뒤 이 테스트는 지워도 되는 것처럼 보인다.

---

## 형식

```python
def test_<지켜야 할 사실>() -> None:
    """<1행: 이 테스트가 지키는 사실. 검사 절차가 아니라 사실.>

    <2~4행: 무엇이 실제로 일어났는가.
             증상 + 그 증상이 보이지 않았던 이유(왜 아무도 몰랐나).>
    <선택 1~2행: 왜 이 방식이어야 하는가. 택하지 않은 대안과 그 이유.>
    """
```

### 규칙 4가지

| # | 규칙 | 이유 |
| :---: | --- | --- |
| 1 | 첫 줄은 **사실**을 쓴다 | `"list_runs 를 테스트한다"` 는 아무것도 말하지 않는다 |
| 2 | **보이지 않았던 이유**를 쓴다 | 그게 이 테스트가 필요한 진짜 근거다 |
| 3 | 수치가 있으면 **수치**를 쓴다 | "느렸다" 보다 "요청당 1.4초" 가 다음 사람을 설득한다 |
| 4 | 사고가 없으면 **짧게 쓴다** | 신규 기능은 한 줄이면 충분하다. 없는 사고를 지어내지 않는다 |

## 좋은 예 — 이 저장소의 실제 주석

### 사고가 있었던 경우

```python
def test_recorded_cost_reaches_the_ledger(runtime, roots) -> None:
    """비용의 정본은 원장이다. 그런데 한동안 아무도 원장에 적지 않았다.

    `LedgerExecutionRecorder` 는 컨테이너가 만들어 유스케이스에 주입까지 했지만
    한 번도 호출되지 않았고, `data/ledger/` 는 어느 시점부터 조용히 멈췄다.
    관측 화면이 텔레메트리 합산으로 폴백하고 있어서 아무도 눈치채지 못했다.
    """
```

→ **보이지 않았던 이유**("폴백하고 있어서")가 핵심이다. 이게 없으면
   "그냥 기록이 빠졌구나" 로 읽히고, 같은 종류의 침묵을 다시 만든다.

```python
def test_source_lookup_is_fast() -> None:
    """예전에는 파일명으로 apps/** 와 packages/** 를 전수 glob 한 뒤
    **파일 크기 내림차순**으로 골랐다. 그래서

        요청: packages/scaffold-engine/.../outline/schema.py   (존재하지 않는 경로)
        반환: apps/api/venv/Lib/site-packages/pydantic/v1/schema.py  (47KB 라서 1등)

    이 되었고, 이 노드는 모든 run 의 검증 스팬에 있었다. 실측 비용도
    요청당 1.4초였다 — node_modules 와 venv 를 매번 훑었기 때문이다.
    """
```

→ **재현 가능한 구체성**. 입력과 잘못된 출력이 그대로 적혀 있다.

### 신규 기능이라 사고가 없는 경우

```python
def test_unknown_document_removes_nothing(tmp_path: Path) -> None:
    """대상이 없으면 아무것도 지우지 않는다."""
```

→ 한 줄이면 된다. **없는 사고를 지어내지 않는다.**

```python
def test_list_runs():

```

```python
def test_delete():
    """삭제가 잘 되는지 확인.

    중요한 테스트이므로 반드시 유지할 것.     # ✗ '중요하다'는 근거가 아니다
    """
```

```python
def test_summary():
    """버그 수정 (#1234)"""                   # ✗ 링크가 죽으면 아무것도 안 남는다
```

## 테스트를 지워도 되는지 판정하는 법

주석이 이 형식을 따르면 판정이 가능해진다.

| 주석이 말하는 것 | 판정 |
| --- | --- |
| 실제 사고 + 보이지 않았던 이유 | **유지.** 그 침묵의 조건이 아직 남아 있다 |
| 계약(어휘·스키마)을 지킨다 | **유지.** 계약이 살아 있는 한 유효 |
| 검사 절차만 적혀 있음 | **재작성 대상.** 무엇을 지키는지 먼저 답한다 |
| 지키던 코드가 삭제됨 | **함께 삭제.** 단, 삭제 이유를 패치노트에 남긴다 |

> 판정이 안 되면 지우지 않는다. **"무엇을 지키는지 모르겠다"는 유지 사유다.**
