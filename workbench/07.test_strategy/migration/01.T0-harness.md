# T0 — 강제 수단 부착

- **상태**: ⬜ 대기
- **선행**: 없음
- **해소하는 감사 항목**: [4-1](../audit/2026-09-14/audit_test_suite_baseline.md) (게이트 부재) · 4-2 (packages 고아) · 4-3 (pytest 설정 부재)

---

## 무엇을

turbo 태스크와 pytest 설정을 신설한다. **테스트 코드는 한 줄도 건드리지 않는다.**

---

## 왜 먼저인가

| 이유 | 설명 |
| --- | --- |
| 가장 싸다 | 설정 파일 4개. 테스트 로직 변경 0 |
| 가장 효과가 크다 | 감사 문제 7건 중 3건이 이 단계에서 해소 |
| 나머지의 선행 조건 | 마커가 없으면 T1·T2 가 "무엇을 뺄지" 표현할 수 없다 |
| 되돌리기 쉽다 | 설정을 지우면 원래대로 |

---

## 절차

### 1. `apps/api/pyproject.toml` 에 pytest 설정 추가

[`templates/pytest.ini_options.toml`](../templates/pytest.ini_options.toml) 의
`apps/api` 블록을 파일 끝에 붙인다.

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-ra --strict-markers -m 'not wiring'"
markers = [
    "wiring: 앱을 부팅하는 L3 배선 테스트 (pnpm test:all 에서만 실행)",
    "external: 외부 프로세스를 실제로 띄우는 테스트",
]
filterwarnings = [
    "error::DeprecationWarning:app.*",
    "error::DeprecationWarning:agent_core.*",
    "error::DeprecationWarning:agent_telemetry.*",
    "error::DeprecationWarning:scaffold_engine.*",
]
```

> 이 시점에는 `wiring` 마커를 단 테스트가 없으므로 **131개가 그대로 돈다.**
> 마커 부착은 T2 에서 한다.

### 2. `packages/*` 에 pytest 설정 + `package.json` 신설

`scaffold-engine`, `agent-core` 두 곳:

```toml
# packages/<pkg>/pyproject.toml 끝에
[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-ra --strict-markers"
```

```json
// packages/<pkg>/package.json  (신설)
{
  "name": "@vibe/<pkg>",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "test": "../../apps/api/venv/Scripts/python.exe -m pytest"
  }
}
```

### 3. `apps/api/package.json` 스크립트 갱신

```json
{
  "scripts": {
    "test": "venv\\Scripts\\python.exe -m pytest --basetemp .pytest_tmp/basetemp",
    "test:all": "venv\\Scripts\\python.exe -m pytest -m \"\" --basetemp .pytest_tmp/basetemp"
  }
}
```

### 4. `turbo.json` 에 태스크 추가

[`templates/turbo.test-task.json`](../templates/turbo.test-task.json) 참조.

### 5. 루트 `package.json` 에 스크립트 추가

```json
{ "scripts": { "test": "turbo run test", "test:all": "turbo run test:all" } }
```

### 6. `pnpm-workspace.yaml` 확인

`packages/*` 가 포함돼 있어야 새 워크스페이스가 잡힌다.

---

## 완료 판정

```bash
# 1. 태스크가 잡히는가 — 워크스페이스 3개가 보여야 한다
pnpm turbo run test --dry-run | grep -i "package\|task"

# 2. 전체가 통과하는가
pnpm test
#    기대: apps/api 131 passed, scaffold-engine 11 passed, agent-core 3 passed

# 3. 캐시가 걸리는가 — 두 번째는 FULL TURBO
pnpm test && pnpm test

# 4. 마커 필터가 준비됐는가 — 에러가 나면 정상 (strict-markers)
cd apps/api && venv/Scripts/python.exe -m pytest -m "wirring" 2>&1 | grep -i "unknown"

# 5. 개발 데이터가 오염되지 않는가
git status --short apps/api/data     # 출력이 없어야 한다
```

---

## 되돌리는 법

```bash
git checkout -- turbo.json package.json apps/api/pyproject.toml apps/api/package.json
rm -f packages/scaffold-engine/package.json packages/agent-core/package.json
# packages/*/pyproject.toml 의 [tool.pytest.ini_options] 블록 제거
```

설정만 건드렸으므로 테스트 코드는 원상태 그대로다.

---

## 기대 수치

| | Before | After |
| --- | --- | --- |
| `turbo run test` | **불가능** | 워크스페이스 3개 |
| 자동 실행되는 테스트 | 131 (수동) | **145** |
| 부분 실행 수단 | 없음 | 마커 준비 완료 (T2 에서 활성) |
| 두 번째 실행 | 10.1초 | **캐시 적중** |
| 변경 워크스페이스만 실행 | 불가 | 가능 |

> 이 단계에서 **실행 시간 자체는 줄지 않는다.** 줄어드는 것은
> "바뀌지 않은 것을 다시 돌리는 횟수"다.

## 주의

| 함정 | 대응 |
| --- | --- |
| `inputs` 를 생략 | 워크스페이스 전체 해시 → 캐시 무의미. 템플릿 목록을 그대로 쓴다 |
| `env` 를 생략 | 등급 루트 환경이 달라져도 캐시 적중 |
| 패키지별 venv 신설 | 하지 않는다. `apps/api` 의 venv 하나를 쓴다 |
| `filterwarnings = ["error"]` | 서드파티 경고까지 에러가 되어 스위트가 멈춘다 |
