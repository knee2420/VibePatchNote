# T4 — 파일 재배치

- **상태**: ⬜ 대기
- **선행**: T1 · T2 · T3
- **해소하는 감사 항목**: [4-5](../audit/2026-09-14/audit_test_suite_baseline.md) (사건별 축적)

---

## 무엇을

파일을 **검증 대상 모듈당 하나**로 정리한다. 매핑표대로 옮긴다.

전체 매핑: [`mapping/apps-api.md`](./mapping/apps-api.md)

---

## 왜

관측 관련 테스트 49개가 5개 파일에 흩어져 있어, **인스펙터를 리팩터링하자 4개 파일이
동시에 깨졌다.** 배치 기준이 없으면 "같은 대상을 건드릴 때 어디를 봐야 하는가"를
매번 다시 찾아야 한다.

---

## 이 단계만 다른 점 — 서두르지 않는다

앞의 T0~T3 는 **한 번에 끝내는** 작업이다. T4 는 다르다.

> **건드릴 때마다 조금씩 옮긴다.**

| 이유 | 설명 |
| --- | --- |
| 위험 대비 이득이 낮다 | 배치를 바꾼다고 버그가 잡히지 않는다 |
| 충돌을 만든다 | 진행 중인 작업과 파일이 겹치면 머지가 어려워진다 |
| 맥락이 필요하다 | 어느 테스트가 어느 대상인지는 그 코드를 만질 때 가장 잘 안다 |

**착수 조건**: 어떤 모듈을 수정하게 되면, 그 모듈의 테스트를 매핑표대로 정리한 뒤 커밋한다.

---

## 절차 (모듈 하나당)

### 1. 매핑표에서 대상을 확인한다

```markdown
| 현재 | 테스트 | 목표 | 등급 |
| test_inspector.py | 18 | test_inspector_service.py (7)
                           test_source_archive.py (5)
                           test_inspector_api.py (6, wiring) | L2/L2/L3 |
```

### 2. 새 파일을 만들고 **복사**한다

```python
"""<대상 모듈>의 <무엇>을 검증한다."""
```

**사고 기록 주석을 함께 옮긴다.** 주석이 그 테스트의 존재 이유다.

### 3. 통과를 확인한 뒤 원본에서 삭제한다

```bash
cd apps/api
venv/Scripts/python.exe -m pytest tests/test_inspector_service.py -q   # 새 파일 통과
# 원본에서 해당 테스트 삭제
venv/Scripts/python.exe -m pytest -m "" -q                             # 전체 통과
```

### 4. 원본이 비면 삭제한다

빈 파일을 남기지 않는다.

## 분할 판정 — 언제 쪼개는가

| 신호 | 조치 |
| --- | --- |
| 한 파일에 테스트 15개 초과 | 검증 대상이 둘 이상 섞였는지 본다 |
| 대상 모듈이 여러 관심사를 가짐 | **구현을 먼저 쪼갠다.** 테스트는 따라온다 |
| 한 대상에 사고가 많이 쌓임 | **그대로 둔다.** 사고 기록은 자산이다 |
| 등급이 섞임 | 마커로 구분. 그래도 크면 대상별로 분리 |

> `test_inspector.py` 18개의 원인은 두 번째였다. 조회·소스 조회·워크플로우 카탈로그가
> 한 서비스에 있었고, **구현을 쪼개자 테스트도 자연히 갈렸다.**
> 테스트 분할이 목적이 되면 안 된다.

---

## 완료 판정

```bash
# 1. 파일당 테스트 수가 15 이하
cd apps/api && grep -c "^def test_\|^async def test_" tests/*.py | sort -t: -k2 -rn | head -5

# 2. 파일명이 대상 모듈과 대응한다 (수동 확인)
ls tests/

# 3. 전체 통과
pnpm test:all

# 4. 사고 기록 주석이 보존됐다 — docstring 없는 테스트가 늘지 않았는가
grep -A1 "^def test_" tests/*.py | grep -c '"""'
```

## 되돌리는 법

모듈 단위로 진행하므로, 문제가 생긴 모듈만 되돌린다.

```bash
git checkout -- apps/api/tests/test_<대상>*.py
```

## 기대 수치

| | Before | After |
| --- | --- | --- |
| 최대 파일 크기 | 18 테스트 | ≤ 15 |
| 관측 테스트 분산 | 5개 파일 | 대상별로 정렬 |
| 한 모듈 수정 시 깨지는 파일 | 최대 4 | 1~2 |

---

## 주의

| 함정 | 대응 |
| --- | --- |
| 한 번에 전부 옮긴다 | 충돌을 만든다. **건드릴 때마다 조금씩** |
| 사고 기록 주석을 흘린다 | 복사할 때 docstring 을 함께 옮긴다 |
| 중복으로 보여 삭제 | 사고가 다르면 둘 다 남긴다 ([`spec/01.principles.md`](../spec/01.principles.md) P5) |
| 테스트 분할을 목적으로 삼는다 | 큰 파일의 원인이 **구현**인지 먼저 본다 |
| 등급을 파일명에 넣는다 | 위치는 대상, 등급은 마커 |
