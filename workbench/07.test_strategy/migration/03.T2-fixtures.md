# T2 — 픽스처 수렴

- **상태**: ⬜ 대기
- **선행**: T0
- **해소하는 감사 항목**: [4-6](../audit/2026-09-14/audit_test_suite_baseline.md) (전역 `TestClient`) · 4-7 (픽스처 중복)

---

## 무엇을

공용 픽스처 3종을 도입하고, **전역 `TestClient` 4개를 제거**한다. 동시에 L3 테스트에
`wiring` 마커를 붙여 T0 에서 준비한 필터를 활성화한다.

---

## 왜

전역 `TestClient(app)` 은 **lifespan 을 실행하지 않는다.** 4개 모듈의 테스트가
프로덕션에 없는 상태(재개 등록·정책 복원·고아 정리가 전부 안 된 앱)를 검증하고 있다.

실제로 그 때문에 **새 설치가 부팅되지 않는 버그**가 131개 전부 초록인 채로 통과했다.

상세: [`examples/90.antipattern-global-client.md`](../examples/90.antipattern-global-client.md)

---

## 대상

| 파일 | 전역 client | 조치 |
| --- | :---: | --- |
| `test_inspector.py` | ✓ | `api_client` 픽스처 + `wiring` 마커 |
| `test_observability_contract.py` | ✓ | 대부분 L1 이므로 **client 자체가 불필요**. 남는 1건만 `api_client` |
| `test_payload_externalization.py` | ✓ | L2 6건은 client 불필요, L3 1건만 `api_client` |
| `test_scaffold_observability.py` | ✓ | 엔진 부분은 client 불필요(T3 에서 packages 로), L3 만 `api_client` |
| `test_bootstrap.py` | ✗ (이미 `with`) | `api_client` 로 통일 + `wiring` 마커 |
| `test_runtime_service.py` | ✗ (이미 `with`) | 동일 |

> **전역 client 를 쓰던 테스트의 상당수는 사실 client 가 필요 없다.** 계약이나 어댑터를
> 검증하면서 편의상 HTTP 를 통과했을 뿐이다. 옮기기 전에 **정말 앱이 필요한지** 먼저 묻는다.

## 절차

### 1. conftest 에 공용 픽스처 추가

[`templates/conftest.workspace.py`](../templates/conftest.workspace.py) 의
`storage` · `container` · `api_client` 를 기존 conftest 에 병합한다.
(저장소 격리는 이미 적용되어 있다.)

### 2. 파일별로 — 앱이 정말 필요한지 판정

각 테스트에 결정 표 2번 질문을 적용한다.

> **앱을 부팅해야 하는가?**

| 답 | 조치 |
| --- | --- |
| 아니오 — 계약만 본다 | client 제거, 대상 모듈을 직접 임포트 (**L1**) |
| 아니오 — 어댑터 행동을 본다 | client 제거, 어댑터를 직접 조립 (**L2**) |
| 예 — 라우팅·부팅이 대상 | `api_client` 픽스처 + `wiring` 마커 (**L3**) |

**단언은 바꾸지 않는다.** 같은 사실을 다른 경로로 확인할 뿐이다.

### 3. `StorageRoots(tmp_path)` 직접 조립을 `storage` 픽스처로

```python
# Before
@pytest.fixture()
def roots(tmp_path: Path) -> StorageRoots:
    storage = StorageRoots(tmp_path)
    storage.ensure()
    return storage

# After — 지역 픽스처를 지우고 공용 `storage` 를 받는다
def test_...(storage) -> None:
```

대상: `test_provenance.py`, `test_run_recovery.py`, `test_runtime_service.py`,
`test_storage_lifecycle.py`

### 4. 대역 이름 통일

| 현재 | 변경 |
| --- | --- |
| `FakeHarness`, `_StubHarness`, `_MockMultiPageHarness` | `_StubHarness` (값만 돌려줌) |
| `_CredentialStore` | `_FakeCredentialStore` |
| `InMemoryPolicyRepository` | `_FakePolicyRepository` |

두 파일 이상에서 쓰는 것은 `tests/doubles.py` 로 모은다.

## 완료 판정

```bash
# 1. 전역 TestClient 가 사라졌다
grep -rn "^client = TestClient" apps/api/tests
#    기대: 출력 없음

# 2. wiring 마커가 붙었다 — 두 수가 달라야 한다
cd apps/api
venv/Scripts/python.exe -m pytest --collect-only -q | tail -1      # L1+L2
venv/Scripts/python.exe -m pytest -m "" --collect-only -q | tail -1  # 전체

# 3. 기본 실행이 예산 안이다
venv/Scripts/python.exe -m pytest tests -q      # 기대: 3초 이내

# 4. 앱 부팅이 세션당 1회다
venv/Scripts/python.exe -m pytest -m "wiring" -q --durations=5
#    기대: 가장 느린 setup 이 1회만 (~1.6초)

# 5. 지역 StorageRoots 조립이 사라졌다
grep -rn "StorageRoots(" apps/api/tests/*.py
#    기대: conftest 의 storage 픽스처만
```

## 되돌리는 법

파일 단위로 되돌린다. 단계적으로 진행했다면 문제가 생긴 파일만 `git checkout`.

```bash
git checkout -- apps/api/tests/<file>.py
```

conftest 의 새 픽스처는 **추가**이므로 기존 테스트를 깨뜨리지 않는다. 남겨도 무해하다.

## 주의

| 함정 | 대응 |
| --- | --- |
| 단언을 함께 바꾼다 | **이행은 배치 작업이다.** 단언을 바꾸면 재작성이지 이행이 아니다 |
| 전부 `wiring` 으로 밀어 넣는다 | 기본 실행이 비어 버린다. 결정 표를 테스트마다 적용한다 |
| `api_client` 를 function 스코프로 | 부팅 1.6초 × 테스트 수. **session 이어야 한다** |
| 마커를 파일 이름에 넣는다 | 등급은 마커, 위치는 대상 |
