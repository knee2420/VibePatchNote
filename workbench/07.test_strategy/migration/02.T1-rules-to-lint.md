# T1 — L0 분리 (규칙 이중 구현 제거)

- **상태**: ⬜ 대기
- **선행**: T0
- **해소하는 감사 항목**: [4-4](../audit/2026-09-14/audit_test_suite_baseline.md) (아키텍처 규칙 이중 구현)

---

## 무엇을

pytest 가 AST 로 재구현한 아키텍처 검사를 `import-linter` 계약으로 옮기고 **삭제**한다.

---

## 왜

같은 규칙이 두 곳에 있으면 **반드시 한쪽이 낡는다.** 실제로 pytest 쪽은 도메인 4개만
알고 있었고, 그 사이 `inspector`·`runtime`·`llm_settings` 3개가 규칙 밖에서 자랐다.

상세 근거와 before/after: [`examples/04.L0-ast-to-contract.md`](../examples/04.L0-ast-to-contract.md)

---

## 대상

| 현재 | 조치 |
| --- | --- |
| `test_adapters.py::test_packages_do_not_import_app_modules` | **삭제** — `Scaffold Engine is independent` + `Agent Core is domain agnostic` 계약이 이미 덮는다 |
| `test_adapters.py::test_only_bootstrap_may_import_domain_implementations` | **삭제** — 도메인 독립 계약 7건이 이미 덮는다 |
| `test_observability_contract.py::test_rule_document_exists` | **삭제 또는 lint 이동** — 문서 존재 확인은 테스트 스위트의 일이 아니다 |
| `test_observability_contract.py::test_generated_types_file_is_marked_as_generated` | **lint 이동 검토** — 파일 헤더 검사는 정적이다 |
| `test_architecture_contracts.py` (4건) | **유지** — 규칙 재구현이 아니라 **규칙 목록의 최신성 검사**다 |

> 마지막 줄이 이 단계의 경계다. "규칙을 다시 짜는 것"과 "규칙 목록이 낡았는지 보는 것"은
> 다르다. 후자는 `import-linter` 로 표현할 수 없으므로 테스트로 남는다.

---

## 절차

### 1. 계약이 실제로 덮는지 먼저 확인

삭제 전에 계약이 같은 위반을 잡는지 **실험으로** 확인한다.

```bash
cd apps/api

# 일부러 위반을 만든다
echo "from app.documents.service import DocumentService" >> app/outline/service.py

# 계약이 잡는가
venv/Scripts/lint-imports.exe          # 기대: "outline must not depend on other domains" 위반

# 되돌린다
git checkout -- app/outline/service.py
```

**잡지 못하면 삭제하지 않는다.** 계약을 먼저 보강한다.

### 2. 삭제

```bash
# test_adapters.py 에서 두 함수와 관련 import(ast, Path) 제거
# → 남는 것은 어댑터 L2 테스트 3개
```

남은 3개는 대상별로 갈라진다 (T4 에서):

| 남는 테스트 | 목표 파일 |
| --- | --- |
| `test_document_source_adapter_saves_and_resolves` | `test_document_source_repository.py` |
| `test_workspace_adapter_persists_sessions` | `test_workspace_repository.py` |
| `test_workspace_adapter_strips_derived_copies` | `test_workspace_repository.py` |

### 3. 문서 존재 검사 처리

```python
# 삭제 대상
@pytest.mark.parametrize("marker", ["observability.md", "§"])
def test_rule_document_exists(marker: str) -> None:
    rule = REPO_ROOT / ".agents" / "rules" / "60-data" / "observability.md"
    assert rule.exists()
```

문서가 사라지면 링크가 깨지는 것으로 충분히 드러난다.
**테스트 스위트의 실행 시간과 실패 신호를 문서 링크 검사에 쓰지 않는다.**

## 완료 판정

```bash
# 1. 계약이 전부 통과
cd apps/api && venv/Scripts/lint-imports.exe
#    기대: Contracts: 11 kept, 0 broken.

# 2. AST 순회가 남아 있지 않다
grep -rn "ast.parse\|ast.walk" apps/api/tests/
#    기대: test_architecture_contracts.py 외에는 없음 (그마저도 tomllib 만 씀)

# 3. 테스트 수가 예상만큼 줄었다
pnpm test
#    기대: apps/api 131 → 128 (또는 126, 문서 검사 처리에 따라)

# 4. 규칙 목록 최신성 검사는 살아 있다
venv/Scripts/python.exe -m pytest tests/test_architecture_contracts.py -q
#    기대: 4 passed
```

## 기대 수치

| | Before | After |

| 규칙의 정본 | 2곳 | **1곳** (`pyproject.toml`) |
| 검사 범위 | 4개 도메인, 직접 import | **7개 도메인**, 간접 포함 |
