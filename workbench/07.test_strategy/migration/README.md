## 2. 왜 이 순서인가

```text
T0 ──▶ T1 ──▶ T2 ──▶ T3 ──▶ T4
설정    중복    픽스처   소유권   재배치
```

| 단계 | 선행 조건 | 이유 |
| --- | --- | --- |
| T0 | 없음 | **테스트 코드를 한 줄도 안 건드린다.** 마커·태스크가 생겨야 나머지가 가능 |
| T1 | T0 | 마커가 있어야 "L0 을 뺀 나머지"를 표현할 수 있다 |
| T2 | T0 | `wiring` 마커가 있어야 `api_client` 로 옮길 대상이 정해진다 |
| T3 | T0 | 워크스페이스 `test` 스크립트가 있어야 옮긴 테스트가 돈다 |
| T4 | T1~T3 | 앞의 셋이 끝나야 옮길 최종 형태가 확정된다 |

**T0 만으로 감사 문제 7건 중 3건(4-1·4-2·4-3)이 해소된다.** 가장 싸고 효과가 크다.

---

## 3. 각 단계의 완료 판정 형식

모든 단계 문서는 아래를 갖춘다.

```markdown
## 무엇을
## 왜 (감사 어느 항목을 해소하는가)
## 절차 (순서대로, 명령 포함)
## 완료 판정 (실행 가능한 확인 명령 + 기대 출력)
## 되돌리는 법
## 기대 수치 (before → after)
```

> **되돌리는 법이 없는 단계는 착수하지 않는다.**

## 4. 이행 중 지켜야 할 것

| 규칙 | 이유 |
| --- | --- |
| 한 단계씩 완료하고 게이트를 돌린다 | 여러 단계를 겹치면 어느 것이 깨뜨렸는지 모른다 |
| **테스트 내용을 바꾸지 않는다** | 이행은 배치·설정 작업이다. 단언을 바꾸면 이행이 아니라 재작성이다 |
| 사고 기록 주석을 보존한다 | 옮길 때 주석을 함께 옮긴다 |
| 삭제는 근거와 함께 | 무엇이 그 테스트를 대체하는지 명시 |

## 5. 열린 결정 — 착수 전 확정 필요

### 결정 1. `.agents/rules/70-test/rule.md` 정본 승격

| | |
| --- | --- |
| **쟁점** | 테스트 배치 규칙은 에이전트가 매번 따라야 하는 규칙이다. workbench 는 작업대(근거)이고, 에이전트가 강제로 읽는 정본은 `.agents/rules/` 다 |
| **제안** | `spec/` 의 요약본을 `.agents/rules/70-test/rule.md` 로 승격하고, 상세는 이 작업대를 링크 |
| **현재** | **보류.** 2026-09-14 시점에 "workbench 만 작업" 으로 범위가 정해짐 |

### 결정 2. 완료 게이트에 `test` 포함

| | |
| --- | --- |
| **쟁점** | `AGENTS.md` 의 `pnpm lint && pnpm typecheck && pnpm build` 에 `test` 를 넣을 것인가 |
| **제안** | 넣는다. 단 기본 실행은 L1+L2(3초 예산)여야 부담이 없다 |
| **참고** | `.agents/skills/develop_50_back_generator` 는 **이미** `pnpm --filter @vibe/api test` 를 요구한다 — 규칙이 두 곳에서 다르게 말하는 상태 |
| **현재** | **보류.** `AGENTS.md` 수정은 범위 밖 |

### 결정 3. `templates/` 코드의 이중 관리

| | |
| --- | --- |
| **쟁점** | `templates/conftest.workspace.py` 는 동작하는 실물이다. 실제 `tests/conftest.py` 와 **두 벌**이 되어 어긋날 수 있다 |
| **제안** | T2 완료 후 템플릿에 `→ 실물은 apps/api/tests/conftest.py` 링크를 박고 사본은 골격만 남긴다 |
| **현재** | 이행 전이므로 실물 유지. **T2 완료 시 재검토** |

### 결정 4. `external` 마커 대상

| | |
| --- | --- |
| **쟁점** | `test_agy_status_snapshot.py` 는 브리지 스크립트를 실제 서브프로세스로 띄운다. 기본 실행에서 뺄 것인가 |
| **제안** | 마커만 달고 **기본 실행에는 유지.** 0.17초로 예산 안이고, 브리지 계약이 깨지면 상태줄이 조용히 멈춘다 |
| **현재** | 미확정 |

## 6. 이행이 끝나면

`migration/mapping/` 은 **의미가 사라진다.** T4 완료 시 다음 중 하나를 택한다.

- 매핑표에 `Superseded` 표시 후 보존 (권장 — 왜 그렇게 배치됐는지의 근거)
- `99.archive/` 로 이동

`spec/` 은 그대로 남는다. 소유권·명명 규칙은 이행과 무관하게 계속 유효하다.
