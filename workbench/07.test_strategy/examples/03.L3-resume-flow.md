# [예제 L3] 승인 → 재개 배선

- **등급**: `L3 배선`
- **대상**: `apps/api/app/bootstrap/resume_handlers.py`, `app/runtime/service.py`, `main.py` lifespan
- **실물**: `apps/api/tests/test_run_recovery.py`, `tests/test_bootstrap.py` (2026-09-14 신설)
- **사고**: 사용자가 승인해도 **아무 일도 일어나지 않았다**

---

## 1. 무엇이 일어났나

`AgentRuntime.resume()` 은 **"이름 + 입력 스냅샷"** 으로만 재개한다. 클로저는 프로세스와
함께 사라지기 때문이다. 그래서 재개하려면 유스케이스가 이름으로 등록돼 있어야 한다.

등록은 **한 군데뿐**이었다 — `DocumentService.__init__` 안. 결과:

| 문제 | 결과 |
| --- | --- |
| 세 유스케이스 중 하나만 등록 | `outline`·`wireframe` 은 대기 상태까지 가 놓고 재개 불가 |
| 등록이 지연 생성 싱글턴 생성자에 있음 | documents API 를 한 번도 안 부르면 **등록 자체가 없음** |
| 승인이 재개를 부르지 않음 | 결정만 파일에 적히고 끝 |

부팅 직후의 고아 정리 시점이 정확히 "등록이 없는 상태"였다.

**각 조각은 단위 테스트를 통과했다.** 깨진 것은 조각이 아니라 **조립**이다.

---

## 2. 왜 L3 인가

| 질문 | 답 | 결론 |
| --- | :---: | --- |
| 코드를 실행하지 않고 증명되는가? | 아니오 | ↓ |
| **앱을 부팅해야 하는가?** | **예** (부팅 시퀀스가 대상) | **L3** |

이 사고의 본체는 **"부팅이 무엇을 했는가"** 다. 부팅을 건너뛰면 재현할 수 없다.

---

## 3. 테스트 — 두 층으로 나눈다

### 3-1. 부팅이 등록했는가 (L3)

```python
def test_every_resumable_use_case_is_registered_at_boot() -> None:
    """재개는 '이름 + 입력 스냅샷'으로만 가능하다. 이름이 없으면 대기가 막다른 길이 된다.

    `AgentRunInput` 에 payload 를 남기는 유스케이스는 재개 핸들러도 있어야 한다.
    예전에는 등록이 `DocumentService.__init__` 안에 있어 세 개 중 하나만 등록됐고,
    그나마도 documents API 를 한 번 부른 뒤에야 등록됐다.
    """
    from app.bootstrap.resume_handlers import register_resume_handlers

    registered = register_resume_handlers(main.container)

    assert registered == [
        "documents.extract_outline",
        "documents.generate_scaffold",
        "documents.scan_segments",
    ]
    assert set(main.container.agent_runtime()._resume_handlers) >= set(registered)
```

> **`== ` 로 목록 전체를 단언한 이유**: `in` 으로 하나씩 보면 **새 유스케이스가 추가됐는데
> 등록을 빠뜨린 경우**를 못 잡는다. 이 사고가 정확히 그 모양이었다.

### 3-2. 승인이 재개를 부르는가 (L2 로 내려도 되는 부분)

런타임과 승인 서비스는 **실물**을 쓰되 앱은 부팅하지 않는다.

```python
def test_approval_resumes_the_run_it_was_blocking(runtime, roots) -> None:
    """승인은 기록이 아니라 재개다.

    대기 토큰은 정의상 실행 하나를 막고 있다. 결정만 파일에 적고 끝내면
    사용자는 "승인했는데 아무 일도 일어나지 않는" 상태를 만난다.
    """
    calls: list[str] = []

    async def handler(payload: dict) -> dict:
        calls.append(payload["docId"])
        return {"ok": True}

    runtime.register_use_case("documents.extract_outline", handler)
    runtime._runs.save_input("run-1", AgentRunInput(...))
    runtime._runs.append("run-1", AgentRunEvent(type="started", agent_name="outline"))
    waiting = runtime.mark_waiting("run-1", failure_code="QUOTA_EXHAUSTED", doc_id="doc-1", ...)

    service = RuntimeService(agent_runtime=runtime, approvals=approvals)

    async def scenario() -> None:
        await service.decide_agreement(waiting.agreement_id, approved=True)
        await asyncio.sleep(0); await asyncio.sleep(0)   # 백그라운드 태스크 한 바퀴
        # 같은 승인을 다시 눌러도 재개는 한 번뿐이다. 결정 기록은 불변이다.
        await service.decide_agreement(waiting.agreement_id, approved=True)
        await asyncio.sleep(0); await asyncio.sleep(0)

    asyncio.run(scenario())
    assert calls == ["doc-1"]        # ← 두 번이 아니라 한 번
```

def test_declined_agreement_does_not_resume(runtime, roots) -> None:
    """거절은 '이어가지 않기로 한 결정'이다."""

## 4. 이 예제가 보여주는 것

| 원칙 | 적용 |
| --- | --- |
| **배선 사고는 배선 자리에서 잡는다** | 조각별 단위 테스트는 전부 통과했었다 |
| 목록은 전체를 단언한다 | 누락을 잡으려면 `in` 이 아니라 `==` |
| 대역보다 실물 | `AgentRuntime` 은 tmp 저장소를 준 실물이 옳다 → `91.antipattern-*` |
| 멱등성을 본다 | 같은 승인 두 번이 재개 두 번이 되면 안 된다 |
| 반대 경로를 본다 | 거절은 재개하지 않는다 |

---

## 5. 등급 경계 — 어디까지가 L3 인가

| 검증 | 등급 | 이유 |
| --- | :---: | --- |
| 부팅이 세 핸들러를 등록했는가 | **L3** | 부팅 시퀀스가 대상 |
| 승인이 재개를 트리거하는가 | **L2** | 서비스 두 개의 협력. 앱 불필요 |
| 재개된 유스케이스가 옳은 결과를 내는가 | **L2** | 유스케이스 자기 테스트 |
| `POST /agreements/{id}` 가 200 을 주는가 | **L3** | HTTP 계약 |

> **같은 사실을 두 등급에서 반복 검증하지 않는다.** 반복하면 하나 깨질 때 둘이 빨개져
> 원인 범위가 넓어진다.
