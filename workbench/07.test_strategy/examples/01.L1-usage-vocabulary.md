# [예제 L1] 토큰 어휘 변환 계약

- **등급**: `L1 계약`
- **대상**: `packages/agent-telemetry/agent_telemetry/contracts/usage.py`
- **실물**: `apps/api/tests/test_observability_contract.py` (이행 후 → `packages/agent-telemetry/tests/`)
- **사고**: 관측 화면의 토큰·캐시 수치가 **전부 0** 으로 표시됨

---

## 1. 무엇이 일어났나

공급자(LLM)는 `prompt_tokens` / `completion_tokens` 어휘를 쓰고, 제품 화면은
`input_tokens` / `output_tokens` 어휘를 쓴다. 둘 사이 변환을 **호출부마다 직접** 했다.

```python
# 여기저기에 흩어져 있던 코드
tokens = meta.get("prompt_tokens")      # 호출부 수만큼 틀릴 기회가 생긴다
```

`usage` 블록이 생긴 뒤에도 옛 평면 키를 읽는 호출부가 남았고, **캐시 토큰과 사고 토큰은
어느 쪽 어휘에도 없어서 통째로 사라졌다.** 화면에는 0 이 떴고, 0 은 "아직 안 썼다"로
읽히므로 아무도 이상하게 여기지 않았다.

---

## 2. 왜 L1 인가

결정 표를 그대로 적용한다.

| 질문 | 답 | 결론 |
| --- | :---: | --- |
| 코드를 실행하지 않고 증명되는가? | 아니오 | ↓ |
| 앱을 부팅해야 하는가? | 아니오 | ↓ |
| 포트/파일/외부 경계를 넘는가? | 아니오 | **L1** |

변환 함수는 순수 함수다. 파일도, 앱도, 시간도 필요 없다. **이 사실이 곧 예산 1초의 근거다.**

---

## 3. 테스트

```python
"""관측 계약 강제 수단."""
from agent_telemetry.contracts import (
    SpanUsage,
    usage_from_product_dict,
    usage_to_product_dict,
)


def test_usage_conversion_is_lossless() -> None:
    """공급자 어휘와 제품 어휘 사이를 왕복해도 값이 사라지지 않는다.

    호출부가 `meta.get("prompt_tokens")` 처럼 남의 어휘를 직접 추측하면
    호출부 수만큼 틀릴 기회가 생긴다 — 실제로 그래서 토큰·캐시가 전부 0 으로
    표시됐다. 어휘 변환은 `agent_telemetry.contracts.usage` 한 곳만 안다.
    """
    produced = SpanUsage(
        prompt_tokens=4798,
        completion_tokens=1692,
        reasoning_tokens=320,
        cache_read_tokens=1200,
        total_tokens=6490,
    )

    consumed = usage_to_product_dict(produced)

    assert consumed["input_tokens"] == 4798
    assert consumed["output_tokens"] == 1692
    assert consumed["thinking_tokens"] == 320         # ← 사라졌던 값
    assert consumed["cache_read_tokens"] == 1200      # ← 사라졌던 값
    assert usage_from_product_dict(consumed) == produced


def test_total_tokens_is_derived_when_provider_omits_it() -> None:
    """합계를 안 주는 공급자가 있다. 없으면 만들되, 있으면 **건드리지 않는다.**

    공급자가 준 합계를 우리가 다시 계산해 덮어쓰면, 공급자만 아는 내부 토큰
    (도구 호출 오버헤드 등)이 조용히 사라진다.
    """
    partial = SpanUsage(prompt_tokens=10, completion_tokens=5)

    assert usage_to_product_dict(partial)["total_tokens"] == 15
```

## 4. 이 문서를 쓰면서 실제로 발견한 것

왕복 테스트를 **문서에 적으면서 실행해 보니** 엄격 비교가 깨졌다.

```text
original : reasoning_tokens = None      ← "모른다"
roundtrip: reasoning_tokens = 0         ← "안 썼다"
```

`SpanUsage` 에서 `reasoning_tokens` 만 `Optional` 이다. 제품 어휘로 넘기면 `0` 이 되고,
되돌려도 `None` 으로 복원되지 않는다. **모르는 값이 0 이 되는 것**은 이 저장소가
비용에서 이미 경계하는 패턴이다 —

> "모르는 값을 0 으로 쓰지 않는다. 0 은 '무료'로 읽힌다."
> (`agent_telemetry/contracts/usage.py` 의 `estimated_cost_usd` 주석)

같은 기준을 토큰에도 적용하면 이것은 **의도된 손실로 기록하거나, `Optional` 을 없애
일관되게 만들거나** 둘 중 하나여야 한다. 현재 템플릿은 전자를 택해
`test_unknown_is_not_the_same_as_zero` 로 그 사실을 못 박아 두었다.

> **이것이 L1 테스트의 값이다.** 어휘 변환을 앱을 통해 확인했다면 이 차이는
> 화면에서 `0` 으로 보였을 뿐, 영원히 드러나지 않았을 것이다.

---

## 5. 이 예제가 보여주는 것

| 원칙 | 적용 |
| --- | --- |
| 계약은 정본이 있는 곳에서 검증한다 | `agent_telemetry` 의 계약이므로 테스트도 그 패키지가 소유 |
| 왕복(round-trip)을 검증한다 | 한 방향만 보면 역방향에서 0 이 되는 필드를 놓친다 |
| **사라졌던 필드를 명시적으로 단언한다** | `thinking_tokens`·`cache_read_tokens` 가 이 사고의 핵심이므로 반드시 검증 |
| 앱을 임포트하지 않는다 | `from main import app` 이 보이면 등급이 틀린 것 |

## 6. 하지 말 것

```python
# ✗ 앱을 통해 계약을 검증한다
def test_usage_conversion():
    response = client.get("/api/v1/inspector/runs")   # L3 비용을 내고 L1 사실을 확인
    assert response.json()[0]["total_tokens"] > 0
```

이러면 **계약이 깨졌을 때 라우터·저장소·어댑터가 함께 빨개져서** 원인을 좁힐 수 없다.
계약은 계약 자리에서 깨져야 한다.
