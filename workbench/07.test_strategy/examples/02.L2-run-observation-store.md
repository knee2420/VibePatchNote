# [예제 L2] 실행 기록 저장소 — 삭제 연쇄와 경로 탈출

- **등급**: `L2 단위`
- **대상**: `apps/api/app/core/observation/run_store.py`
- **실물**: `apps/api/tests/test_run_observation_store.py` (2026-09-14 신설)
- **사고**: 문서를 지워도 **프롬프트에 실린 본문이 디스크에 남아 있었다**

---

## 1. 무엇이 일어났나

문서 삭제는 연쇄여야 한다. 원본만 지우고 파생물을 남기면 지운 문서의 내용이 계속 남는다.
`DeleteDocumentUseCase` 에는 그 연쇄가 **있었다**:

```python
removed_traces = delete_traces_for_document(doc_id)   # 트레이스 연쇄 삭제
```

그런데 트레이스 시스템이 쓰이지 않게 된 뒤로 `state/log/traces/` 는 **항상 비어 있었다.**
즉 이 호출은 빈 디렉터리를 뒤지는 no-op 이었고, 늘 `0` 을 돌려주니 아무도 이상하게 여기지
않았다. 그 사이 프롬프트 본문은 `data/runs/*/payloads/` 에 내용 해시로 쌓이고 있었다.

**"연쇄가 있다"와 "연쇄가 닿는다"는 다른 말이다.**

---

## 2. 왜 L2 인가

| 질문 | 답 | 결론 |
| --- | :---: | --- |
| 코드를 실행하지 않고 증명되는가? | 아니오 | ↓ |
| 앱을 부팅해야 하는가? | 아니오 | ↓ |
| 포트/파일/외부 경계를 넘는가? | **예** (파일 삭제) | **L2** |

라우터를 통해 검증할 수도 있지만, 그러면 삭제 로직 하나를 보기 위해 앱 부팅 1.6초를 낸다.
**행동은 포트 자리에서 본다.** 라우터가 이 유스케이스를 부르는가는 L3 가 따로 본다.

---

## 3. 테스트

```python
"""`data/runs/{run_id}/` 의 관측 자료를 아는 곳은 하나다."""
from __future__ import annotations

import json
from pathlib import Path

from app.core.observation import RunObservationStore


def _write_run(runs_dir: Path, run_id: str, doc_id: str) -> Path:
    """생산자가 쓰는 모양 그대로 만든다. 손으로 지어낸 구조를 쓰지 않는다."""
    run_dir = runs_dir / run_id
    (run_dir / "payloads").mkdir(parents=True, exist_ok=True)
    (run_dir / "meta.json").write_text(
        json.dumps({"run_id": run_id, "doc_id": doc_id}), encoding="utf-8"
    )
    (run_dir / "payloads" / "abc123.txt").write_text("문서 본문 사본", encoding="utf-8")
    return run_dir


def test_document_deletion_cascades_to_run_payloads(tmp_path: Path) -> None:
    """문서를 지우면 그 문서의 본문이 실린 실행 기록도 사라진다.

    프롬프트에는 문서 본문이 실리고, 그 본문은 `payloads/` 에 내용 해시로
    외부화되어 남는다. 원본만 지우면 지운 문서의 내용이 계속 디스크에 있다.
    예전 트레이스 연쇄 삭제가 지키려던 것이 이것인데, 트레이스 자체가 쓰이지
    않게 된 뒤로 그 연쇄는 빈 디렉터리를 뒤지는 no-op 이 되어 있었다.
    """
    runs_dir = tmp_path / "runs"
    mine = _write_run(runs_dir, "run-1", "doc-1")
    other = _write_run(runs_dir, "run-2", "doc-2")

    removed = RunObservationStore(runs_dir).delete_for_document("doc-1")

    assert removed == 1
    assert not mine.exists()
    assert other.exists(), "다른 문서의 기록은 건드리지 않는다"      # ← 과삭제 방어


def test_unknown_document_removes_nothing(tmp_path: Path) -> None:
    """대상이 없으면 아무것도 지우지 않는다."""
    runs_dir = tmp_path / "runs"
    _write_run(runs_dir, "run-1", "doc-1")

    assert RunObservationStore(runs_dir).delete_for_document("doc-없음") == 0
    assert (runs_dir / "run-1").exists()


def test_unsafe_run_id_cannot_escape_the_runs_root(tmp_path: Path) -> None:
    """식별자는 경로가 아니다. 상위로 올라가는 이름은 통과하지 않는다."""
    runs_dir = tmp_path / "runs"
    runs_dir.mkdir(parents=True)
    outsider = tmp_path / "outsider"
    outsider.mkdir()

    store = RunObservationStore(runs_dir)

    assert store.delete("../outsider") is False
    assert store.meta("../outsider") == {}
    assert outsider.exists()
```

## 4. 이 예제가 보여주는 L2 의 필수 3종

| 종류 | 이 예제 | 왜 필수인가 |
| --- | --- | --- |
| **정상 경로** | 내 문서의 기록이 지워진다 | 하기로 한 일을 하는가 |
| **과삭제 방어** | 남의 문서는 남는다 | 삭제·갱신 테스트는 "지워지는가"만 보면 절반이다 |
| **식별자 안전성** | `../outsider` 거부 | 경로를 만드는 어댑터는 전부 필요 |

> 루트를 **주입**받는다는 점에 주의: `RunObservationStore(runs_dir)`.
> 어댑터가 `settings.storage.runs` 를 스스로 열면 테스트는 `tmp_path` 를 쓸 수 없고,
> 결국 실제 `data/` 에 쓰게 된다 → `92.antipattern-real-data.md`

---

## 5. 하지 말 것

```python
# ✗ 실제 저장소에 쓴다
store = RunObservationStore(settings.storage.runs)

# ✗ 삭제만 보고 과삭제를 안 본다  (다른 문서가 지워져도 통과한다)
assert store.delete_for_document("doc-1") == 1

# ✗ 라우터를 통해 본다  (앱 부팅 1.6초 + 원인 범위가 넓어짐)
client.delete("/api/v1/documents/doc-1")
```
