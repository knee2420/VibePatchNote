# [예제 L0] AST 검사 → import-linter 계약 이관

- **등급**: `L0 규칙` (pytest 아님)
- **대상**: `apps/api/tests/test_adapters.py:65,82` → `apps/api/pyproject.toml`
- **사고**: 규칙을 두 곳에 구현했더니 **한쪽만 낡았다**

---

## 1. 무엇이 일어났나

같은 규칙이 두 곳에 있었다.

| 규칙 | import-linter | pytest |
| --- | --- | --- |
| packages 는 app 을 import 하지 않는다 | ✅ 계약 | ✅ `test_packages_do_not_import_app_modules` |
| 도메인 내부를 직접 import 하지 않는다 | ✅ 계약 7건 | ✅ `test_only_bootstrap_may_import_domain_implementations` |

2026-09-14 에 `import-linter` 계약을 손보면서 도메인 열거를 7개로 확장하고
경로 계약을 와일드카드(`app.*.service`)로 바꿨다. 그런데 pytest 쪽은 그대로였다:

```python
domains = {"documents", "outline", "wireframe", "workspaces"}   # ← 3개 누락
```

`inspector`, `runtime`, `llm_settings` 는 **이 검사 밖에서 자라고 있었다.**
실제로 `inspector` 는 컨테이너를 거치지 않고 서비스가 저장 경로를 직접 열고 있었는데
테스트는 초록이었다.

---

## 2. 판정 — 왜 L0 인가

결정 표의 **첫 질문**에서 갈린다.

| 질문 | 답 | 결론 |
| --- | :---: | --- |
| **코드를 실행하지 않고 증명되는가?** | **예** (import 그래프는 정적이다) | **L0** |

정적으로 증명되는 것을 pytest 로 쓰면 세 가지를 잃는다.

1. **전용 도구의 정확도** — `import-linter` 는 간접 import·순환까지 본다. 손으로 짠 AST
   순회는 직접 import 만 본다.
2. **실패 시점** — 규칙 위반은 `lint` 에서 즉시 나와야 한다. 테스트 스위트 끝까지 기다릴 일이 아니다.
3. **정본의 단일성** — 규칙이 두 곳에 있으면 반드시 한쪽이 낡는다. 위가 그 증거다.

---

## 3. Before → After

### Before — pytest 가 AST 를 직접 순회

```python
# apps/api/tests/test_adapters.py

def test_only_bootstrap_may_import_domain_implementations() -> None:
    app_dir = Path(__file__).resolve().parents[1] / "app"
    domains = {"documents", "outline", "wireframe", "workspaces"}   # 손으로 유지
    violations: list[str] = []

    for source_file in app_dir.rglob("*.py"):
        if "bootstrap" in source_file.parts:
            continue
        own_domain = next((d for d in domains if d in source_file.parts), None)
        tree = ast.parse(source_file.read_text(encoding="utf-8"))
        for node in ast.walk(tree):
            if not isinstance(node, ast.ImportFrom) or not node.module:
                continue
            parts = node.module.split(".")
            if len(parts) < 3 or parts[0] != "app" or parts[1] not in domains:
                continue
            if parts[1] != own_domain:
                violations.append(f"{source_file}: {node.module}")

    assert not violations
```

- 40줄. 도메인 목록을 손으로 유지. 간접 import 를 못 본다.

### After — 계약 + 낡음 방지 테스트

```toml
# apps/api/pyproject.toml  (도메인마다 한 블록, 7개)

[[tool.importlinter.contracts]]
name = "inspector must not depend on other domains"
type = "forbidden"
source_modules = [
    "app.inspector.service",
    "app.inspector.adapters",
    "app.inspector.ports",
]
forbidden_modules = [
    "app.documents", "app.llm_settings", "app.outline",
    "app.runtime", "app.wireframe", "app.workspaces",
]
```

**그리고 계약 목록 자체가 낡지 않게 하는 것만 테스트로 남긴다:**

```python
# apps/api/tests/test_architecture_contracts.py

def test_every_domain_has_an_independence_contract() -> None:
    """새 도메인은 규칙 밖에서 태어나지 않는다."""
    assert _independence_contracts().keys() == _domains_on_disk()


def test_each_contract_forbids_every_other_domain() -> None:
    """한 도메인만 빠뜨려도 그 짝은 영영 검사되지 않는다."""
```

> **여기서 멈추는 이유**: "규칙 자체"는 `import-linter` 가 보고, 테스트는
> **"규칙 목록이 현실과 일치하는가"** 만 본다. 검사를 재구현하지 않는다.

## 4. 효과 (실측)

| | Before | After |
| --- | --- | --- |
| 규칙의 정본 | 2곳 | **1곳** (`pyproject.toml`) |
| 검사 범위 | 4개 도메인, 직접 import 만 | **7개 도메인**, 간접 포함 |
| 실행 시점 | 테스트 스위트 중 | **`pnpm lint`** |
| 위반 발견 | 없음(낡아서) | `inspector` 위반 즉시 검출 |
| 코드 | 40줄 AST 순회 | 계약 선언 + 목록 일치 검사 |

와일드카드 계약으로 바꾸자마자 **숨어 있던 위반 3건**(`llm_settings` 가 전역 `settings`
를 읽고 **덮어쓰던** 것)이 추가로 드러났다.

## 5. 이관 판정 체크리스트

기존 테스트를 L0 으로 옮겨도 되는지 판정할 때:

- [ ] 코드를 **실행하지 않고** 파일/AST/설정만 보고 답이 나오는가?
- [ ] `import-linter` 의 계약 타입(`forbidden` / `independence` / `layers`)으로 표현 가능한가?
- [ ] 표현 불가라면, **목록의 최신성** 같은 메타 검사만 테스트로 남길 수 있는가?
- [ ] 옮긴 뒤 원래 테스트를 **삭제**했는가? (남기면 이중 구현이 다시 시작된다)

> 마지막 항목이 핵심이다. "혹시 몰라 둘 다 둔다"가 이 사고의 출발점이었다.
