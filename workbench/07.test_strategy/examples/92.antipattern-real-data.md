# [반례 92] 실제 `data/` 오염 — 개발 PC 의 누적 상태가 결과를 정했다

- **분류**: 🔴 반례
- **발견**: 2026-09-14
- **해당 파일**: `conftest.py`(격리 없음) + `settings.storage` 를 직접 쓰던 5개 모듈
- **증상**: 코드를 안 고쳤는데 **테스트가 갑자기 실패**

---

## 1. 무엇이 일어났나

`conftest.py` 의 `observability_runs` 픽스처는 픽스처 run 을 **실제 저장소**에 복사했다.

```python
runs_dir = settings.storage.runs        # ← 개발 PC 의 apps/api/data/runs
runs_dir.mkdir(parents=True, exist_ok=True)
shutil.copytree(src, runs_dir / src.name, dirs_exist_ok=True)
```

픽스처는 끝나면 자기가 복사한 것을 지운다. 문제는 **테스트가 만들어낸 run 은 지우지
않는다**는 점이었다. 앱을 부팅하는 테스트들이 돌 때마다 실제 `data/runs/` 에 run 이 쌓였다.

---

## 2. 어떻게 깨졌나

`GET /inspector/runs` 는 기본 `limit=50` 으로 **최신순 50건**을 돌려준다.
run 이 66건이 되자, 2026-09-12 생성된 픽스처 run 3건은 **53~55위**로 밀려났다.

```text
total runs on disk: 66 listed: 56
agent-5a0846d55d53        rank: 55
run-1a094630557-4e4f96ee  rank: 53
run-contract-...-191719   rank: 54
```

```text
FAILED test_inspector.py::test_inspector_runs_and_detail
    AssertionError: run-1a094630557-4e4f96ee 가 목록에 없습니다
FAILED test_inspector.py::test_snapshots_keep_their_contract_shape - StopIteration
FAILED test_observability_contract.py::test_unknown_cost_is_null_not_zero - StopIteration
```

**코드는 한 줄도 바뀌지 않았다.** 바뀐 것은 개발 PC 의 디스크 상태다.

---

## 3. 왜 이게 심각한가

| 층위 | 문제 |
| --- | --- |
| **재현성** | 같은 커밋이 어제는 통과하고 오늘은 실패한다. 원인을 코드에서 찾게 된다 |
| **데이터 등급 위반** | `data/` 는 "지우면 복구 불가 · 백업 대상" 등급이다(`60-data/rule.md`). **테스트가 거기에 쓰는 것 자체가 위반** |
| **신뢰 붕괴** | 한 번 이런 실패를 겪으면 실패를 "또 그거겠지"로 넘기기 시작한다 |
| **은폐** | 이 오염이 반례 90(부팅 순서 버그)을 가리고 있었다. 저장소가 빈 적이 없었으므로 |

> 마지막 줄이 핵심이다. **오염된 테스트는 다른 버그의 은신처가 된다.**

---

## 4. 올바른 형태

등급 루트 네 개를 임시 디렉터리로 돌린다. `settings` 는 **모듈 임포트 시점**에 환경 변수를
읽으므로, 설정이 임포트보다 **먼저** 일어나야 한다.

```python
"""테스트 공용 픽스처.

## 저장소 격리

**테스트는 개발 PC 의 `data/` 에 쓰지 않는다.** 예전에는 썼다. 그래서 테스트를 돌릴
때마다 실제 run 이 쌓였고, 66건을 넘긴 순간 목록 상한(50)에 밀려 픽스처 run 이
화면에서 사라지면서 관측 테스트가 통째로 깨졌다 — 코드가 아니라 **개발 PC 의 누적
상태**가 결과를 정한 것이다.
"""
import os
from pathlib import Path

_TEST_STORAGE_ROOT = Path(__file__).resolve().parents[1] / ".pytest_tmp" / f"storage-{os.getpid()}"
for _key, _grade in (
    ("VIBE_CONFIG_DIR", "config"),
    ("VIBE_DATA_DIR", "data"),
    ("VIBE_CACHE_DIR", "cache"),
    ("VIBE_STATE_DIR", "state"),
):
    os.environ[_key] = str(_TEST_STORAGE_ROOT / _grade)

import pytest                              # noqa: E402
from app.core.config import settings       # noqa: E402
```

```python
@pytest.fixture(scope="session", autouse=True)
def _isolated_storage():
    """세션이 끝나면 임시 저장소를 통째로 버린다."""
    yield _TEST_STORAGE_ROOT
    shutil.rmtree(_TEST_STORAGE_ROOT, ignore_errors=True)
```

### 함정 — 디렉터리를 미리 만들지 않는다

처음에 `settings.ensure_directories()` 를 conftest 에 넣었다가 **전 모듈이 부팅 거부**됐다.
등급 루트가 먼저 생기면 "버전 없는 비어있지 않은 저장소"가 되어 `StorageVersionError` 가 난다.

→ 이것이 반례 90 의 부팅 순서 버그를 드러낸 경로다. **격리가 버그를 꺼냈다.**

---

## 5. 교훈

> **테스트는 지워도 되는 곳에만 쓴다.** 어느 등급에 쓰는지 판정할 수 없다면
> 그 테스트는 이미 잘못 설계된 것이다.

파생 규칙 두 가지:

1. 어댑터는 저장 루트를 **주입**받아야 한다. 스스로 `settings.storage.X` 를 열면
   테스트가 `tmp_path` 를 쓸 방법이 없어지고, 결국 실제 `data/` 에 쓰게 된다.
2. `pnpm test` 를 돌린 뒤 **`git status` 가 깨끗해야** 한다. 더러워지면 격리가 깨진 것이다.

---

## 6. 점검 명령

```bash
# 테스트가 실제 저장소를 직접 참조하는가
grep -rn "settings.storage" apps/api/tests/*.py

# 테스트 후 실제 저장소가 변했는가
cd apps/api && ls data/runs | wc -l && pnpm test && ls data/runs | wc -l
# 두 수가 같아야 한다
```
