# 🃏 Mask Edit Core Stack (4성 이상 레퍼런스 카드)

이 카드는 Document Builder의 핵심 기능인 **'Mask Edit (부분 영역 추출 및 세그먼트 제어)'**을 구현하기 위해 적용 타당성이 매우 높은(별점 4개 이상) 3가지 핵심 기술을 압축 요약한 카드입니다.

---

## 🌟 [5성] MDX (Markdown + JSX)
**영역 분할 및 데이터 구조화의 핵심**

* **구현 원리:** 평문 마크다운(Markdown) 내부에 React/Vue 컴포넌트를 직접 삽입할 수 있는 포맷입니다. 내부적으로 `unified.js` 같은 AST(추상 구문 트리) 엔진을 사용해 파싱합니다.
* **Mask Edit 적용 포인트:**
  - **데이터 구조화:** 문서의 특정 구역을 `<Segment id="mask-1" pinned={true}>...</Segment>`처럼 컴포넌트 태그로 감싸서 관리할 수 있습니다.
  - **정밀 타겟팅:** 파싱 단계에서 `mask-1` 영역만 정확히 추출(Extract)하여, 문서 전체를 건드리지 않고 해당 부분만 AI 프롬프트에 던져 교체(Inpainting)하는 로직을 가장 깔끔하게 구현할 수 있습니다.

---

## 🌟 [5성] Obsidian Canvas (JSON 기반 노드 모델링)
**스캐폴드(뼈대) 데이터 모델링의 완벽한 롤모델**

* **구현 원리:** 무한 줌/팬이 가능한 캔버스 인터페이스. 겉보기엔 그래픽 툴 같지만, 실제 데이터는 각 카드의 ID/위치/텍스트 내용이 담긴 `nodes` 배열과 연결선인 `edges` 배열로 구성된 순수 JSON 파일(`.canvas`)로 저장됩니다.
* **Mask Edit 적용 포인트:**
  - **독립적 세그먼트 제어:** 시뮬레이터의 아웃라인 뼈대를 JSON 형태의 노드(Node) 집합으로 관리하는 아이디어를 차용합니다.
  - **부분 재생성 최적화:** "Node A(도입부)는 핀(Pin) 고정, Node B(본문)만 마스크 영역으로 지정해 다시 생성"할 때, 파일 전체 파싱이나 텍스트 충돌 걱정 없이 JSON 객체 내의 `Node B` 데이터만 안전하게 교체할 수 있습니다.

## ⭐ [4성] xTiles (xTiles.app)
**공간적(Spatial) UI 및 블록 마스킹 인터페이스**

* **구현 원리:** 위에서 아래로 흐르는 전통적 문서를 탈피, 화이트보드(Miro)처럼 캔버스 위에 자유롭게 배치 가능한 '타일(Tile)' 객체들의 집합으로 문서를 구성합니다. (Drag & Drop 및 절대 좌표 레이아웃 활용)
* **Mask Edit 적용 포인트:**
  - **시각적 마스킹 UX:** 제품 안내문, 기획서 등 '지면의 특정 위치(Zone)' 자체가 문서의 형식 기준이 되는 문서를 다룰 때 완벽한 UI 롤모델입니다.
  - **직관적 조작:** 사용자가 캔버스 위에서 마우스로 특정 타일(블록)을 선택(Masking)한 뒤 "이 타일만 AI가 다시 채워줘"라고 지시하는 인터페이스를 설계하는 데 영감을 줍니다.
