이처럼 캔버스를 중심으로 수많은 도구 창과 옵션이 조화롭게 배치된 구조는 UI/UX 및 프론트엔드 분야에서 주로 **워크스페이스 레이아웃(Workspace Layout)** 또는 패널 기반 UI(Panel-based / Docking UI)라고 부릅니다.

  

상황과 관점에 따라 다음과 같은 구체적인 디자인 패턴 및 시스템 용어로 분류됩니다.

  

- **앱 셸(App Shell) & 캔버스 워크스페이스:** 상단 내비게이션, 좌측 기능 바, 하단 상태 표시줄처럼 고정된 외곽 골격(Shell)을 두고, 중앙 뷰포트(Canvas)에 작업물을 집중시키는 구조입니다.
    
      
    
- **사이드 레일(Side Rail) & 드로어(Drawer) 시스템:** 좌측에 아이콘만 모아둔 좁은 바(Rail)를 두고, 아이콘을 누르면 세부 기능 창이 서랍처럼 슬라이드되어 열리는 형태입니다. 기능이 아무리 많아도 평소에는 캔버스 영역을 가리지 않아 복잡도를 크게 낮춰줍니다.
    
      
    
- **문맥 인식 UI(Contextual UI / Inspector Pattern):** 모든 메뉴를 항상 화면에 띄우지 않고, 사용자가 캔버스에서 텍스트를 누르면 글꼴/크기 툴바가, 이미지를 누르면 필터/자르기 도구가 동적으로 나타나는 인터페이스 패턴입니다.
    
      
    
- **스튜디오/크리에이티브 스위트 UI(Studio / Desktop-class UI):** 피그마, 어도비 제품군, 영상 편집기처럼 고밀도 데이터와 수많은 그래픽 조작 도구를 웹 화면 하나에 응축해 놓은 복합 생산성 도구의 전형적인 UI 양식을 총칭합니다.
    
      
    

기능 요소가 수십 가지에 달하더라도 사용자의 시선이 머무는 캔버스를 방해하지 않도록, **'필요한 순간에만 문맥에 맞게 패널을 꺼내 쓰는 점진적 공개(Progressive Disclosure)'** 원칙을 시스템화한 형태입니다.
