VS Code나 포토샵 같은 **도킹 패널·탭 분할 UI**와 **TipTap 기반 PKM(Personal Knowledge Management)** 환경을 구축할 때 가장 적합한 오픈소스 및 React 패키지 조합입니다.

  

### 1. 도킹 레이아웃 & 탭/패널 관리 (Window & Docking System)

VS Code처럼 탭을 드래그해서 상하좌우로 분할하거나 사이드바로 옮기는 레이아웃을 직접 구현하면 상태 관리가 매우 복잡해집니다. 아래 라이브러리를 활용하는 것이 좋습니다.

  

#### **Dockview (`dockview` / `dockview-react`)** — _가장 추천_

- **특징**: VS Code의 레이아웃 엔진을 웹 환경에 맞춰 벤치마킹하여 만든 라이브러리입니다.
    
      
    
- **장점**:
    
      
    - 탭 드래그 앤 드롭, 상하좌우 무한 스플릿(Splitview), 플로팅 윈도우, 패널 접기/펼치기 지원.
        
          
        
    - VS Code 테마 및 UI 패턴(워터마크, 빈 탭 화면 등)과 일치도가 가장 높음.
        
          
        
    - React 18/19 및 TypeScript를 완벽 지원하며 커스텀 컴포넌트 렌더링이 자유로움.
        
          
        
- **PKM 활용**: 중앙 에디터 다중 분할(Split Editor), 좌측 탐색기/백링크 패널, 우측 그래프 뷰 도킹에 최적.
    
      
    

#### **FlexLayout-react (`flexlayout-react`)**

- **특징**: 증권사 트레이딩 룸, 무거운 웹 IDE(Eclipse Theia 스타일)에서 자주 쓰이는 전통적인 도킹 매니저.
    
      
    
- **장점**:
    
      
    - JSON 하나로 전체 창 레이아웃(배치, 크기, 탭 위치)을 직렬화(Serialize)/역직렬화할 수 있어 워크스페이스 저장 및 복원이 매우 간단함.
        
          
        
    - 탭 그룹화 및 플로팅(팝아웃) 윈도우 기능이 강력함.
        
          
        
- **단점**: 스타일링이 다소 클래식하여 모던한 에디터 느낌을 내려면 커스텀 CSS 작업이 필요함.
    
      
    

#### **react-resizable-panels**

- **특징**: shadcn/ui에 내장된 리사이즈 패널 라이브러리.
    
      
    
- **장점**: 가볍고 모던하며 Radix UI 생태계와 결합하기 좋음.
    
      
    
- **한계**: 자유로운 탭 분할/도킹(드래그해서 창 나누기) 기능은 직접 구현해야 하므로, "고정된 좌/우/하단 패널 + 중앙 탭" 구조일 때만 적합.
    
      
    

### 2. TipTap 기반 PKM 에디터 스캐폴딩

PKM 앱은 일반 위지윅(WYSIWYG)과 달리 **마크다운 상호 호환, 위키링크(`[[노트]]`), 슬래시 명령어, 블록 드래그**가 핵심입니다.

  

#### **Novel (`novel`)**

- **특징**: Vercel/Tremor 생태계에서 나온 TipTap 기반의 노션/AI 스타일 오픈소스 에디터.
    
      
    
- **장점**:
    
      
    - 슬래시 메뉴(`/`), 인라인 풍선 툴바, 멘션 기능이 기본 번들링되어 있음.
        
          
        
    - Tailwind CSS 기반으로 디자인이 세련되어 프로토타이핑 속도를 극대화할 수 있음.
        
          
        
- **PKM 활용**: Notion 스타일의 블록 조작감과 모던한 입력 환경을 빠르게 도입할 때 유리.
    
      
    

#### **TipTap 확장 조합 (커스텀 PKM 구축 시)**

- **`tiptap-markdown`**: TipTap 내부 JSON 구조와 일반 `.md` 파일 간의 무손실 양방향 변환 지원 (Obsidian 호환 파일 시스템 구축 시 필수).
    
      
    
- **`@tiptap/extension-mention` (위키링크 커스텀)**:
    
      
    - 트리거를 `@` 대신 `[[`로 변경하여 노트 간 연결(Bi-directional Linking) 및 백링크 자동완성 구현.
        
          
        
- **`@tiptap/extension-collaboration` + `Yjs`**:
    
      
    - 여러 탭에서 같은 문서를 열었을 때 충돌 없이 상태를 실시간 동기화하고, 로컬 저장소(IndexedDB)와 CRDT 방식으로 결합하기 위해 권장.
        
          
        

### 3. 사이드바 및 PKM 탐색 도구 (File Tree & Graph)

#### **React Arborist (`react-arborist`)** — 파일 트리

- **특징**: VS Code의 파일 탐색기 기능을 그대로 재현한 React 트리 컴포넌트.
    
      
    
- **장점**:
    
      
    - 수천 개의 노트/폴더를 다뤄도 버벅임 없는 가상화(Virtualization) 기본 내장.
        
          
        
    - 폴더 간 드래그 앤 드롭 이동, 인라인 이름 변경, 다중 선택 지원.
        
          
        

#### **React Flow (`@xyflow/react`)** 또는 **`react-force-graph`** — 지식 그래프 뷰

- **`react-force-graph`**: Obsidian의 2D/3D 지식 네트워크 그래프(Force-directed Graph)를 구현할 때 가장 가볍고 자연스러움.
    
      
    
- **`@xyflow/react`**: 단순 네트워크를 넘어 노트를 카드 형태로 캔버스 위에 올려 연결하는 '캔버스형 PKM(Heptabase 스타일)'으로 확장할 때 최적.
    
      
    

### 추천 아키텍처 조합

|**영역**|**권장 패키지**|**역할**|
|---|---|---|
|**전체 윈도우/도킹**|`dockview`|VS Code 스타일 다중 탭 분할 및 사이드 패널 배치|
|**중앙 에디터**|`TipTap` + `tiptap-markdown`|마크다운 기반 PKM 위지윅 에디터 코어|
|**파일 탐색기 패널**|`react-arborist`|가상 스크롤 지원 폴더/노트 트리 뷰|
|**노트 연관 그래프**|`react-force-graph-2d`|문서 간 백링크/링크 시각화|
|**상태 관리**|`zustand` + `yjs` (IndexedDB)|로컬 퍼스트 데이터 저장 및 다중 패널 간 동기화|

**구현 팁**: 레이아웃 전체를 처음부터 자유 도킹으로 열어두면 UX가 산만해질 수 있습니다. 기본 레이아웃은 `좌측: 파일트리(고정/접이식)` + `중앙: dockview 기반 에디터 스플릿 탭` + `우측: 백링크/아웃라인 패널` 형태로 프리셋을 구성하는 것을 권장합니다.
