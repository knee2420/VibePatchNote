# Workbench: 95.data_source Guidelines

## 1. 목적
`workbench/95.data_source/`는 문서 파싱, LLM 파이프라인 튜닝, 성능 벤치마크 및 단위/통합 테스트의 입력으로 투입되는 **외부 원본 데이터(Raw Input Documents: PDF, Word, 이미지, 텍스트 등) 보관소**입니다.

---

## 2. 🚨 절대 준수 원칙

### ① 읽기 전용(Read-Only) 원칙
- **원칙:** `workbench/95.data_source/` 내의 파일은 가공되지 않은 순수 원본 상태(Raw State)를 유지해야 합니다.
- **금지 사항:** 에이전트는 본 디렉토리 내의 원본 파일을 직접 수정, 변형, 덮어쓰기, 삭제해서는 안 됩니다.
- **가공 시 절차:**
  - 텍스트 전처리, 슬라이싱, 지오메트리 추출 등의 가공이 필요한 경우, 원본 파일을 해당 태스크 디렉토리(예: `05.llm_tuning/{task}/01.dataset/`)로 복사한 후 가공 작업을 수행합니다.

### ② `98.collection`과의 엄격한 역할 분리

| 구분 | `95.data_source` | `98.collection` |
| :--- | :--- | :--- |
| **주요 대상** | 테스트/평가/검증용 **순수 원본 문서 파일 (PDF 등)** | 리서치 자료, 사용자 스토리, AI 분석 보고서/초안 |
| **운용 패턴** | 정적 원본 소스 (Raw Source Repository) | 수집/분류 라이프사이클 (**Inbox Pattern**: checking ➔ picked) |
| **에이전트 권한** | Read-Only (읽기 전용) | `checking/`에만 단일 제출 가능 |

### ③ 용량 및 테스트 대표성 관리
- 무의미한 대용량 파일이나 중복 파일을 무분별하게 누적하지 않고, 문서 구조의 다양성(표 중심, 서식 중심, 텍스트 중심 등)을 대변할 수 있는 대표 샘플 위주로 관리합니다.
