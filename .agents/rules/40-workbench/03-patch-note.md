# Workbench: 03.patch_note Guidelines

## 1. 목적
`workbench/03.patch_note/`는 VibePatchNote 시스템의 기능 추가, 성능 최적화, 아키텍처 리팩토링 등의 개발 변경 사항을 날짜별/작업별로 추적하고 기록하는 **불변 이력 관리(Audit Trail) 저장소**입니다.

---

## 2. 🚨 절대 준수 원칙 (Strict Golden Rules)

### ① 작성 타이밍: 사용자의 명시적 지시 시에만 작성
* **원칙:** **"사용자가 특별히 패치노트 작성하라고 언급을 할 때만 작성을 할 것"**
* **금지 사항:** 코드를 수정하자마자 에이전트 스스로 패치노트를 선제적으로 자동 작성해서는 **절대 안 됩니다.**
* **이유:** 사용자가 실제 수정된 코드와 화면/기능 동작을 직접 테스트하고 검증(컨펌)하기 전까지는 공식 릴리즈가 아니기 때문입니다.

### ② 작성 전 필수 절차: README.md 선제 정독
* **원칙:** 사용자가 패치노트 작성을 지시했을 때, **반드시 `workbench/03.patch_note/README.md`를 먼저 열어서 완독(view_file)한 후** 작업을 시작해야 합니다.
* **확인할 내용:**
  - 현재 날짜 디렉토리(`YYYY-MM-DD/`)에 등록된 최신 패치노트 번호(예: 01, 02, ... 07)
  - 기존 패치노트 카드들의 표준 템플릿 규격 및 작성 톤앤매너
  - 색인(Index) 테이블 구성 방식

### ③ 불변성 원칙 (1작업 = 1독립 카드 신규 생성)
* **원칙:** 기존에 작성된 패치노트 카드를 덮어쓰거나 누적 수정하지 않습니다.
* **방법:** 항상 해당 날짜 폴더(`workbench/03.patch_note/YYYY-MM-DD/`) 하위에 **새로운 독립 마크다운 카드(`patch_note_{작업명}.md`)**를 생성합니다.
* **색인 갱신:** 새 카드를 생성한 후, 반드시 `workbench/03.patch_note/README.md`의 최하단 테이블에 새 번호와 링크를 추가하여 색인을 동기화합니다.
