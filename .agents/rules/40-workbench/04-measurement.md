# Workbench: 04.measurement Guidelines

## 1. 목적
`workbench/04.measurement/`는 성능 회귀·버그·병목·원인 불명 현상을 **추측이 아닌 측정으로 규명한 과정과 결과**를 불변 카드로 보존하는 진단 아카이브입니다.

`03.patch_note`와 역할이 다릅니다.

| 저장소 | 답하는 질문 |
| --- | --- |
| `03.patch_note` | **"무엇을 바꿨는가"** — 확정된 변경 이력 |
| `04.measurement` | **"무엇을 측정했고, 무엇이 원인이 아니었는가"** — 가설 검증 이력 |

측정 결과 코드를 고쳤다면 **두 카드를 모두** 남깁니다.

---

## 2. 🚨 절대 준수 원칙

### ① 추측 금지, 배제로 좁힌다
* "아마 이것 때문일 것이다"로 코드를 고치지 마십시오. **가설 수립 → 측정 → 참/거짓 판정 → 배제** 절차를 따릅니다.
* 고친 뒤 "좋아진 것 같다"로 카드를 닫지 마십시오. **측정값 없는 결론은 결론이 아닙니다.**

### ② 배제된 가설을 반드시 전부 기록한다
* 원인이 **아니라고** 판명된 항목이 이 저장소의 핵심 자산입니다.
* 이유: 같은 증상 재발 시 **이미 배제된 경로를 다시 조사하는 낭비를 막기 위함**입니다.
* "확인해봤더니 아니었다"는 지울 내용이 아니라 **남길 내용**입니다.

### ③ 재현 실패는 재현 실패로 기록한다
* 원인을 못 찾았으면 **"찾지 못했다"고 그대로** 씁니다. 그럴듯한 원인을 지어내어 카드를 완결시키지 마십시오.
* 미해결 카드도 정식 카드입니다. 상태를 `🟡 미해결(재현 실패)`로 명시하고 색인에 등록합니다.

### ④ 측정 환경의 한계를 명시한다
* 계측이 실패했거나 값을 신뢰할 수 없다면 **그 수치를 근거로 쓰지 말고 "신뢰 불가"로 표기**합니다.
* 실제 사례: 백그라운드 탭에서 `requestAnimationFrame`이 throttle되어 프레임 계측이 전면 무효화됨.

### ⑤ 베이스라인 대조
* 회귀 조사는 **기준 커밋(회귀 이전)과 정면 대조**합니다. 커밋 해시를 카드에 명시해 재현 가능하게 만듭니다.

### ⑥ 1조사 = 1카드 불변성
* 기존 카드를 덮어쓰지 않습니다. 후속 조사는 **새 카드 + `선행 조사` 필드**로 연결합니다.
* 미해결 카드가 나중에 해결되면 새 카드를 쓰고 **색인 상태만** 갱신합니다. (본문 보존)

### ⑦ 작성 타이밍
* 사용자가 진단/측정을 지시했거나, 원인 조사를 수행한 경우에 작성합니다.
* 새 카드 생성 후 반드시 `workbench/04.measurement/README.md` 최하단 **색인 테이블을 동기화**합니다.

## 3. 구조 및 네이밍

```text
workbench/04.measurement/
├── README.md                                  # 운영 원칙 · 표준 템플릿 · 색인
└── YYYY-MM-DD/
    ├── measurement_{조사_주제}.md             # 개별 진단 카드 (snake_case)
    └── artifacts/                             # (선택) 계측 스크립트 · 원시 로그 · 스크린샷
```

표준 카드 템플릿과 색인 형식은 [`workbench/04.measurement/README.md`](../../../workbench/04.measurement/README.md)를 따릅니다.
