# Atomic Components & Vibe Coding Optimization

## 원칙
1. **극단적 컴포넌트 세분화 (Single Responsibility)**:
   - 하나의 파일은 하나의 명확한 책임만 가집니다.
   - 컴포넌트 파일 하나가 과도하게 길어지지 않도록 적극적으로 서브 컴포넌트로 쪼갭니다 (**권장 100줄 이내, 상한 150줄**).
   - **단, AHA 원칙([`00-core` P6](../00-core/rule.md))이 이 줄 수 기준보다 우선합니다.** 줄 수를 맞추려고 아직 안정되지 않은 코드를 억지로 공통화하지 마십시오. 반복이 3회 이상이고 구조가 굳었을 때만 추출합니다.
   - 카드, 리스트 아이템, 헤더, 액션 버튼 그룹 등 시각적/기능적 단위마다 개별 컴포넌트로 분리합니다.

2. **바이브 코딩(LLM Pair Programming) 최적화**:
   - AI 에이전트가 특정 컴포넌트를 수정할 때 다른 코드 컨텍스트가 오염되지 않도록 작고 명확한 파일 단위를 유지합니다.
   - 명확한 네이밍과 TypeScript 인터페이스를 선언하여 AI가 파일의 역할을 한눈에 파악할 수 있게 합니다.
