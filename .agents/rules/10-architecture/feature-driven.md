# Feature-Driven Vertical Slice Architecture

## 원칙
1. **기능(Feature) 단위 격리**:
   - 프론트엔드와 백엔드 모두 기술 계층(Layer) 중심이 아닌 **기능(Feature) 중심**으로 디렉토리를 분할합니다.
   - 하나의 기능 폴더 안에 해당 기능 수행에 필요한 컴포넌트, 훅, API 통신 함수, 타입 정의가 모두 응집되어야 합니다.

2. **독립성 및 결합도 최소화**:
   - `features/A`는 `features/B`를 **Public API를 통해서도 참조하지 않습니다.** (내부 파일 참조는 물론 금지)
   - 기능 간 데이터 공유가 필요할 경우:
     - 공통분모가 **도메인 상태**면 → `entities`로 내린다
     - 공통분모가 **범용 타입/유틸**이면 → `shared`로 내린다
     - 둘 다 아니면 → **상위 `widgets`가 두 feature를 조합**한다
   - 특정 기능 폴더 전체를 삭제하거나 비활성화해도 다른 기능 및 앱 전체 빌드에 영향이 없어야 합니다.

3. **백엔드 매핑**:
   - 백엔드도 동일하게 **도메인 단위 수직 분할**을 따릅니다: `apps/api/app/[도메인명]/` 하위에
     `router.py` · `schemas.py` · `service.py` · `ports.py` · `use_cases/` · `adapters/` 를 격리합니다.
     LLM 이 개입하는 업무가 있으면 `agents/` 가, 영속 모델이 있으면 `models.py` 가 더해집니다.
     (세그먼트 정본은 [`00-core/rule.md` §3.2](../00-core/rule.md))
   - 프론트엔드의 슬라이스 이름은 **동작**(`canvas-file-drop`), 백엔드의 도메인 이름은 **자원**(`documents`, `workspaces`)을 따르므로 1:1로 같을 필요는 없습니다. 대응 관계만 유지합니다.
   - **도메인 간 직접 참조는 프론트와 똑같이 금지입니다.** 다른 도메인의 동작이 필요하면
     자기 `ports.py` 에 계약을 정의하고 DI 컨테이너가 구현체를 주입합니다.

> 이 문서의 상위 규칙은 [`00-core/rule.md`](../00-core/rule.md) 입니다. 충돌 시 그쪽을 따릅니다.
