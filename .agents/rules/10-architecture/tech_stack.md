# 프론트엔드 아키텍처 및 코어 기술 스택 룰

이 문서는 에이전트가 프론트엔드 코드를 작성하거나 기획 문서를 해석할 때 **가장 최우선으로 적용되어야 하는 절대 기준**입니다. 
다른 문서에 과거의 실험적 스펙(예: HTML5 Canvas, React-Konva, Slate.js 등)이 남아있더라도, 에이전트는 무조건 아래의 확정 스펙을 따릅니다.

## 1. 확정된 프론트엔드 UI/에디터 스택
- **코어 엔진:** `React Flow` + `Tiptap` 조합을 사용합니다.
- **용도 분리:**
  - `React Flow`: 무한 줌/팬 캔버스, 노드(세그먼트)의 시각적 배치, 크기 조절, 연결선 제어 등 거시적(Macro) 아키텍처를 담당합니다.
  - `Tiptap`: 각 노드(React Flow Node) 내부에 삽입되어, 실제 텍스트 블록의 리치 텍스트 편집, 블록 마스킹(Mask Edit) 등 미시적(Micro) 제어를 담당합니다.
- **금지 사항:** `React-Konva`, `Fabric.js` 등 HTML5 Canvas 기반의 순수 드로잉 엔진은 내부 텍스트 에디터(Tiptap)와의 렌더링 충돌 및 DOM 이벤트 제어의 복잡성 때문에 **절대 사용하지 않습니다.**

## 2. 발생 가능한 충돌 시 대처 (디버깅 지침)
- 만약 과거 기획 카드나 다른 문서에서 `React Flow` 외의 다른 기술(React-Konva 등)을 요구하는 문장을 발견하면, 그 즉시 무시하고 **해당 문서를 `React Flow + Tiptap` 스펙으로 수정(Patch)** 해야 합니다.
- 시스템이나 에이전트가 코드를 생성할 때 `Canvas API`를 사용하려고 시도한다면, DOM 기반의 `React Flow Node`로 렌더링 방식을 전환해야 합니다.
