# .agents/rules — 규칙 저장소 인덱스

이 폴더의 문서는 **에이전트가 코드를 작성할 때 적용되는 워크스페이스 룰**입니다.
폴더 번호가 **우선순위**입니다. **숫자가 작을수록 강합니다.**

---

## 🔴 읽는 순서 (필수)

```text
1️⃣  00-core/rule.md      ← 반드시 먼저. 코드를 쓰기 전 필독.
2️⃣  나머지는 필요할 때만 펼친다.
```

| 우선순위 | 폴더 | 성격 | 다루는 것 |
| --- | --- | --- | --- |
| **00** | [`00-core/`](./00-core/) | **헌법 (필독·최우선)** | 레이어 경계, 배치 결정표, 절대 금지, 완료 게이트 |
| 10 | [`10-architecture/`](./10-architecture/) | 아키텍처 사상 | 기능 중심 분할, 헤드리스 로직, 확정 기술 스택 |
| 20 | [`20-modularity/`](./20-modularity/) | 모듈화 지침 | 원자 컴포넌트, Plug&Play, ShadCN 우선 |
| 30 | [`30-workflow/`](./30-workflow/) | 작업 절차 | 패키지 큐레이션, 워크플로우 원칙 |
| 40 | [`40-workbench/`](./40-workbench/) | 산출물 관리 | `workbench/` 하위 디렉터리 운용 규칙 |
| 50 | [`50-develop/`](./50-develop/) | 실무 컨벤션·노하우 | 프론트/백엔드 세부 컨벤션, 트러블슈팅 |

---

## ⚖️ 충돌 해결 규칙

두 문서의 내용이 다르면 **번호가 작은 문서를 따릅니다.**

- `00-core` 와 `50-develop/convention` 이 충돌 → **`00-core` 승**
- `00-core` 에 언급이 없는 세부 사항 → 하위 문서를 따름

과거 기획 문서(`workbench/**`)에 남아 있는 폐기된 스펙은 **규칙이 아닙니다.**
규칙은 오직 이 폴더(`.agents/rules/`)에만 있습니다.

---

## 📁 작성 원칙

- 가이드 본문 파일명은 `rule.md`로 통일합니다 (트리 순회 시 구조 파악 목적).
- 예제 코드/데이터는 해당 가이드 폴더 하위 `examples/`에 격리합니다.
- 새 규칙을 추가할 때는 **자동 검증 수단(린트 규칙, 타입, CI)을 함께 붙입니다.**
  문서만 있고 강제 수단이 없는 규칙은 지켜지지 않습니다.
  (근거: [`00-core/examples/violation-catalog.md` V-10](./00-core/examples/violation-catalog.md))
