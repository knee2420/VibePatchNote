# Package Curation & User Approval Workflow

## 원칙
1. **임의 외부 패키지 설치 금지**:
   - 에이전트는 사전 승인 없이 임의로 `npm install`, `pnpm add`, `pip install` 등을 통해 외부 라이브러리/패키지를 설치하지 않습니다.

2. **사전 큐레이팅 및 비교 브리핑**:
   - 추가적인 라이브러리나 패키지가 필요하다고 판단될 경우, 설치하기 전에 사용자에게 다음과 같은 양식으로 큐레이팅을 제공합니다:
     - **필요성**: 왜 해당 패키지가 필요한지 (해결하려는 문제)
     - **후보 비교**: 대안 라이브러리와의 비교 (유지보수 상태, 번들 크기, 사용성 등)
     - **자체 구현 가능 여부**: 외부 패키지 없이 가볍게 직접 구현할 수 있는 범위인지 여부
     - **추천안**: 에이전트의 권장 사항과 그 이유

3. **사용자 승인 후 설치**:
   - 사용자가 제안된 옵션 중 하나를 승인하거나 설치를 명시적으로 지시한 경우에만 패키지 설치 명령을 실행합니다.

4. **설치는 반드시 pnpm 워크스페이스 문법으로**:
   - 이 저장소는 pnpm workspace 모노레포입니다. `npm install` / `yarn`을 사용하면 **락파일이 갈라집니다.**
   - 대상 패키지를 명시해 설치합니다: `pnpm -F @vibe/web add <pkg>` / `pnpm -F @vibe/api ...`
   - 루트에 설치하는 것은 개발 도구(turbo 등)에 한합니다.
   - 파이썬 의존성은 `apps/api/requirements.txt`에 추가한 뒤 설치합니다.
