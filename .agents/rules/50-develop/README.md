# 50-develop 규칙 저장소

이 폴더는 에이전트 및 시스템 개발 과정에서 습득한 **트러블슈팅, 베스트 프랙티스, 기술 가이드라인**을 보관하는 지식(Rule) 저장소입니다.

## 📂 디렉터리 구조 및 작성 원칙

각 가이드는 단순한 마크다운 카드를 넘어, 관련된 예제 코드와 데이터를 독립적으로 관리하기 위해 **"1 가이드 = 1 폴더(본문 + 격리된 예제)"** 원칙을 엄격하게 따릅니다.

```text
50-develop/
├── README.md               # 현재 문서 (구조 및 원칙 안내)
├── auto-fix-loop.md        # 무결성 검증 자율 루프
├── convention/             # 파트별 개발 컨벤션
│   ├── architecture/rule.md
│   ├── front/rule.md
│   └── back/rule.md
└── [주제별_카테고리]/      # 예: agy-cli/
    └── [가이드_이름]/      # 예: 01_scripting_guide/
        ├── rule.md         # 가이드 본문 (해결책, 원칙, 규칙 설명)
        └── examples/       # 해당 가이드와 연관된 독립된 예제 코드 및 산출물 보관용 폴더
            ├── test_pdf_reader.py
            └── pdf_output.md
```

> 이 폴더의 규칙은 [`00-core`](../00-core/rule.md)보다 **하위**입니다. 충돌 시 `00-core`를 따릅니다.

## 📝 관리 규칙
1. **격리성(Isolation) 유지:** 수많은 예제 코드와 데이터가 뒤섞이는 것을 원천 차단하기 위해, 반드시 각 가이드 폴더 하위의 `examples` 디렉터리 내부에 종속되도록 구성합니다.
2. **문서명 통일:** 가이드 본문 카드의 파일명은 항상 `rule.md`로 통일하여, 폴더 트리를 순회하거나 파이프라인에서 읽어들일 때 구조를 명확히 파악할 수 있도록 합니다.
3. **에이전트 컨텍스트 주입:** 이 폴더에 작성된 `rule.md` 파일들은 Antigravity 커스텀 워크스페이스 룰로 작동하므로, 미래의 에이전트가 유사한 작업을 수행할 때 시행착오 없이 즉시 올바른 해답(예: `--dangerously-skip-permissions` 플래그 사용 등)을 적용하도록 강제합니다.
