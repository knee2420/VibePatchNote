# Pipeline 96: Generator

## 1. 목적

`workbench/99.archive`나 `workbench/97.reference`에 저장된 원문(Raw Docs, Git Repo, Tech Specs)을 **원문을 다시 열어볼 필요가 없는 고밀도 메타 지식 데이터베이스**로 재조립하여 **`workbench/96.data_pipeline/[주제명]/`** 에 구축한다.

**[매우 중요한 1:1 물리적 폴더 매핑 원칙]**
데이터 파이프라인은 원본 아카이브의 라우팅 트리와 **한 치의 오차도 없는 1:1 물리적 디렉터리 구조**를 가져야 한다. 임의로 `01_` 같은 접두어를 붙이거나, 보기 좋게 요약해서 폴더를 뭉개버리면 안 된다. 아무리 깊은 경로라도, 원본 폴더마다 무조건 그 안의 파일/하위 폴더를 가리키는 `index.md`가 존재하여 '하향식 라우터 체인'을 형성해야 한다.

산출물은 세 층위로 구성된다:
1. **특별한 관제탑 - 루트 인덱스 (`[최상위_주제폴더]/index.md`)**: 아카이브 최상위 루트의 파일들과 하위 폴더들을 안내할 뿐만 아니라, **전체 파이프라인의 모든 디렉터리에 위치한 지식 카드들의 상대 경로를 평탄화하여 `# 전체 카드` 섹션에 전부 리스트업하는 조감도(Bird's-eye View)** 역할을 수행한다. 또한 프론트매터 하단에 메타데이터(출처 및 파일/카드 수 통계)와 서론(`# 이 프로젝트는`)을 반드시 포함해야 한다.
2. **중간/리프 로컬 인덱스 (`[모든_하위폴더]/index.md`)**: 루트 인덱스와는 달리, 원본의 중간 폴더나 최종 폴더에 위치하며, 직계 하위 디렉터리와 현재 디렉터리의 카드들만을 중계하는 철저한 로컬 허브.
3. **지식 카드 (`C-파일명.md`)**: 원본 마크다운/코드 파일과 1:1 매칭되는 고밀도 지식 요소 캡슐.

> **핵심 판단 기준**: 에이전트가 단 한 번 루트 `index.md`를 열람하는 것만으로 전체 주제의 개요와 모든 카드의 정확한 깊은 상대 경로를 한눈에 파악하여 원하는 타겟 카드로 직행(Fetch)할 수 있는가.

## 2. 절대 규칙 (위반 시 산출물 폐기)

1. **원문 문장 복사(Copy-Paste) 금지**: `summary`와 `elements` 설명은 원문의 결론과 아키텍처 의도를 압축한 정제된 문장이어야 한다.
2. **환각 링크 금지**: 실재하지 않는 경로나 헤딩을 가리키지 않는다. `anchor`는 원문에 실재하는 헤딩/함수명이어야 한다. (§6 검증 스크립트 필수 통과)
3. **elements 밀도 보장**: 카드의 elements를 1~2개로 대충 때우지 않는다. 밀도 기준은 §3을 엄격히 준수한다.
4. **프론트매터 5대 필수 필드**: 모든 `index.md`와 `C-*.md`는 프론트매터 5필드(`type, title, description, resource, timestamp`)를 필수 선언한다.
5. **판단과 맥락 서술**: 단순 목록 나열("~을 다룹니다")이 아니라, **어떤 아키텍처 결정이 내려졌는지 · 핵심 제약은 무엇인지 · 무엇이 중복/결손인지** 판단을 기록한다.
6. **장식용 이모지 금지**: 가독성을 해치는 장식용 이모지는 배제하며, 오직 `⚠️`(결손/주의/제약 표시)만 허용한다.

## 3. elements 밀도 기준 (원문 분량 비례)

카드의 elements 개수는 **원문 파일 크기에 정비례**한다. 균일하게 맞추지 않는다.

| 원문 크기 | 권장 elements | 비고 |
|---|---|---|
| ~3KB | 2~3개 | 서문, 목차, 짧은 유틸 정의 |
| 3~7KB | 4~6개 | 단일 기능 모듈, 일반 아키텍처 절 |
| 7~15KB | 6~10개 | 복합 컴포넌트, 코드/표가 결합된 핵심 스펙 |
| 15~25KB | 12~17개 | 대형 모듈, 프레임워크 전체 코어 스펙 |
| 25KB~ | 17개+ | 카드의 분할(Split)을 먼저 검토 |

* **1개 element = 독립적으로 인용·재사용될 수 있는 최소 단위** (아키텍처 패턴 1건, 인터페이스/타입 1개, 핵심 규칙 1세트, 안티패턴 1건 등).
* `kind` 분류: `아키텍처 · 원칙 · 규칙 · 구조 · 인터페이스 · 코드 · 템플릿 · 절차 · 사례 · 비교 · 안티패턴 · 도구 · 데이터 · 참조`

## 4. 표준 산출물 템플릿

### 📄 산출물 1: 지식 카드 (`C-XX-XX_핵심키워드.md`)

```markdown
---
type: card
title: [카드 제목]
description: [이 카드가 다루는 핵심 내용물/아키텍처 한 줄 요약]
resource: "../../../99.archive/[원본 상대 경로]" # 또는 97.reference / 98.collection
timestamp: YYYY-MM-DD
---

# summary
[원문의 결론, 아키텍처 의도, 핵심 작동 방식을 2~4줄로 압축. 가장 핵심적인 원칙 하나에만 굵게 표시.]

# elements
| id | kind | label | 무엇이 들어있나 | anchor |
|---|---|---|---|---|
| E1 | 아키텍처 | [패턴/구조명] | [해당 구조의 책임, 입출력, 설계 의도] | `## [원문 헤딩]` |
| E2 | 규칙 | [제약/규약명] | [절대 준수/금지해야 할 엔지니어링 룰] | `## [원문 헤딩]` |
| E3 | 코드 | [인터페이스/DTO] | [복사해 쓸 수 있는 핵심 타입 선언이나 스켈레톤] | `### [원문 헤딩]` |
| E4 | 안티패턴 | [실패 사례] | [이렇게 구현했을 때 발생하는 결합도 문제] | `## [원문 헤딩]` |

# 밖으로
- [E1] 요소는 `[C-XX-XX 카드명](상대경로)`의 E_와 **동일한 관심사를 다른 관점에서** 다룬다.
- [E2] 규칙의 전제가 `[C-YY-YY 카드명](상대경로)`에 정의되어 있다 — 먼저 참조 필요.
- ⚠️ [원문에 명시되지 않은 숨은 의존성이나 결손 사항이 있으면 여기에 기록]

# 원문
[아카이브/레퍼런스 원본 상대경로](상대경로) · [외부 공식 URL]
```

## 5. 작업 절차 (Phase 1 ~ 5)

- [ ] **Phase 1 — 구조 설계**: 아카이브 원문의 전체 디렉터리 트리를 분석 ➔ 임의 축약 없이 1:1로 매핑되는 파이프라인 폴더 구조 확립
- [ ] **Phase 2 — 로컬 인덱스 연쇄 생성**: 루트부터 리프 노드까지 모든 디렉터리마다 `index.md`를 생성하여 상/하위 폴더를 라우터로 연결
- [ ] **Phase 3 — 카드 추출**: 개별 파일 분석 ➔ elements 및 anchor 추출 ➔ 원본 파일과 동일한 위치에 `C-파일명.md` 생성
- [ ] **Phase 4 — 루트 인덱스 및 가로축 작성**:
  - `index.md` 최상단에 원본 출처 및 전체 파일/카드 수 메타데이터 작성.
  - `# 이 섹션은/이 프로젝트는`에 파이프라인 전체의 고밀도 개요 작성.
  - `# 지도`에 폴더 볼륨 및 태그 명시.
  - **가장 중요**: `# 전체 카드` 섹션에 **파이프라인 전체의 모든 카드 목록**을 해당 디렉터리 그룹별로 전부 리스트업하여 에이전트가 한눈에 전체 경로를 볼 수 있게 조감도 구성.
  - 전체를 관통하는 거시적 연결고리(가로축)와 라우팅 테이블 작성.
- [ ] **Phase 5 — 무결성 검증**: §6 검증 스크립트 실행하여 깨진 링크 0건, 프론트매터 누락 0건 확인

## 6. 검증 스크립트

파이프라인 구축 완료 후 반드시 실행하여 무결성을 검증한다.

```bash
cd "workbench/96.data_pipeline" && python - <<'EOF'
import os, re, urllib.parse

for topic in sorted(d for d in os.listdir('.') if os.path.isdir(d)):
    bad, fm, ec, n, tot = [], [], [], 0, 0
    for dp, _, fns in os.walk(topic):
        for fn in sorted(fns):
            if not fn.endswith('.md'): continue
            p = os.path.join(dp, fn)
            txt = open(p, encoding='utf-8').read()
            
            # 1. 링크 실재성 검사
            for m in re.finditer(r'\]\(([^)]+)\)', txt):
                t = m.group(1).strip()
                if t.startswith('http'): continue
                t = urllib.parse.unquote(t.split('#')[0])
                if not os.path.exists(os.path.normpath(os.path.join(dp, t))):
                    bad.append((p, t))
                    
            # 2. 프론트매터 5대 필수 필드 검사
            head = txt.split('---')[1] if txt.startswith('---') else ''
            need = ['type', 'title', 'description', 'resource', 'timestamp']
            miss = [k for k in need if not re.search(rf'^{k}:', head, re.M)]
            if miss: fm.append((p, miss))
            
            # 3. elements 밀도 검사
            if fn.startswith('C-') and '# elements' in txt:
                rows = [l for l in txt.split('# elements')[1].split('# 밖으로')[0].strip().split('\n') if l.strip().startswith('|')][2:]
                n += 1
                tot += len(rows)
                if len(rows) < 3: ec.append((p, len(rows)))
                
    print(f"### [{topic}] 총 카드 {n}장 · 평균 elements {tot/n if n else 0:.1f}개")
    for p, t in bad: print("  [깨진 링크]", p, "->", t)
    for p, m in fm:  print("  [FM 누락]", p, "누락 필드:", m)
    for p, c in ec:  print("  [밀도 부족]", p, f"elements {c}개")
EOF
```
