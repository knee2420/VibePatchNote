# 이 책은

**"AI에게 무작정 코드를 짜라고 시키는 바이브코딩은 반드시 실패한다"**는 문제의식에서 출발한다. 컨텍스트 윈도우의 한계(AI의 망각)와 직장인의 단기 기억 한계(인간의 망각)가 결합될 때 벌어지는 참사를 진단하고, 이를 타개하기 위한 **'기억하는 개발'** 워크플로우를 6개의 파트에 걸쳐 전개한다.

핵심 아키텍처는 **장기 기억(Obsidian) + 지휘자(Claude Desktop) + 실행자(Claude Code)**의 3각 편대이며, 이들을 MCP(Model Context Protocol)로 연결하여 끊임없이 **'기록-설계-구현-기록'**의 4단계 루프를 도는 것이 중심 공식이다.

10분 만에 앱을 만든다는 과장된 시연 영상을 넘어, 에러에 대처하고, 아키텍처를 설계하며, 결국 며칠 뒤에 다시 열어도 5분 만에 작업에 복귀할 수 있는 **지속 가능한 AI 엔지니어링**을 비개발자도 따라 할 수 있게 안내한다.

1. **설계의 선행과 증명**

2. **역할 분담의 진화**
   단순한 3각 편대 선언([C-02-05](02_도구를_준비한다/C-02-05_완벽한_통제망_구축.md))에서 시작해, 실전 프로젝트에서의 구체적 지휘-실행 분리([C-04-01](04_실전_프로젝트/C-04-01_기록의_위력과_역할_분담.md))를 거쳐, 팀 단위의 다자간 오케스트레이션([C-05-03](05_더_잘하기/C-05-03_팀_오케스트레이션.md))으로 확장된다.

3. **기록의 자산화 프로세스**
   단기 세션 로그 중심의 기록([C-03-01](03_워크플로우를_익힌다/C-03-01_기록.md))이 누적되면서, 아키텍처 판단을 담는 ADR([C-05-01](05_더_잘하기/C-05-01_템플릿_고도화.md))과 프로젝트를 횡단하는 공통 지식([C-05-02](05_더_잘하기/C-05-02_다중_프로젝트_관리.md))으로 진화한다.

4. **에러 대응의 시스템화**
   터미널 에러에 쩔쩔매던 프롤로그([C-00-01](00_프롤로그/C-00-01_프롤로그.md))의 모습이, 명확한 3단계 판단 기준([C-04-05](04_실전_프로젝트/C-04-05_에러_대응_프로세스.md))을 통해 지휘자에게 에스컬레이션하는 성숙한 프로세스로 완성된다.
