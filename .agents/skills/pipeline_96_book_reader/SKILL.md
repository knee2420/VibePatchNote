# Pipeline 96: Book Reader

## 1. 목적
에이전트가 외부 지식을 지어내거나 전체 폴더를 무지성으로 검색(grep)하는 것을 원천 차단하고, 오직 `workbench/96.data_pipeline` 내부에 고도로 구조화된 **인덱스(index.md)와 지식 카드(C-XX-XX.md)만을 기반으로 답변**하도록 강제한다.

## 2. 절대 행동 수칙 (위반 시 답변 무효)
1. **무지성 전체 검색(Grep/Find) 금지:** 검색 도구로 키워드를 때려 맞추지 마라. 반드시 목차(index.md)를 따라가야 한다.
2. **환각(Hallucination) 엄격 금지:** 카드에 없는 내용은 "파이프라인 안에서는 알 수 없다"고 선을 그어야 한다. 자신이 아는 외부 지식을 섞지 마라.
3. **출처 명시 의무:** 답변의 모든 문단이나 핵심 주장은 자신이 참고한 카드 이름과 앵커(예: `[C-02-02_State_file](...)`)를 반드시 마크다운 링크로 달아야 한다.
4. **추측성 라우팅 금지:** 경로를 지어내어 열지 마라. 항상 `index.md`에 실재하는 경로만 접근하라.

## 3. 탐색 프로토콜 (반드시 이 순서대로 실행)

**Phase 1: 지도(Map) 획득**
- 질문을 받으면 가장 먼저 `workbench/96.data_pipeline` 내 타겟 책(폴더)의 루트 **`index.md`** (예: `workbench/96.data_pipeline/루프_엔지니어링/index.md`)를 열람하여 `# 지도`, `# 가로축`, `# 전체 카드`를 파악한다.

**Phase 2: 라우팅(Routing)**
- 루트 인덱스를 통해 타겟이 되는 챕터(하위 폴더)를 찾았다면, 해당 폴더의 로컬 `index.md`를 조회한다.
- 질문의 답을 찾기 위해 **반드시 읽어야 하는 특정 카드(C-XX-XX.md)들의 목록**을 2~4개로 추려낸다.

**Phase 3: 정밀 타격(Fetch)**
- 추려낸 특정 카드 파일들만 정확하게 파일 읽기 도구(`view_file`)로 열람한다.
- 카드 안의 `# summary`와 `# elements` 표를 분석하여 질문에 대한 답을 구성할 데이터를 추출한다.
- 만약 `# 밖으로` 섹션에 연결된 다른 카드가 문제 해결에 필수적이라면, 꼬리를 물고 해당 카드도 추가로 열람한다.

**Phase 4: 출처 기반 답변(Synthesis)**
- 추출한 데이터를 바탕으로 사용자의 질문에 대한 답변을 작성한다.
- 답변의 끝이나 각 문단의 끝에는 `(출처: [카드명](상대/절대 경로))` 형태로 반드시 참조를 남긴다.

## 4. 모범 답변 예시

**User:** "/pipeline_96_book_reader State 파일이 뭔지 설명해줘."

**Agent Thought Process:**
1. (Thought) `workbench/96.data_pipeline/루프_엔지니어링/index.md` 열람 ➔ `# 전체 카드`에서 `02_루프_구성요소` 확인.
2. (Thought) `02_루프_구성요소/index.md` 열람. `C-02-02_State_file.md`가 타겟임을 식별.
3. (Thought) `C-02-02_State_file.md` 정밀 열람하여 elements 추출.
4. (Response) 정보 획득 완료. 답변 작성 및 출처 표기 시작.

**Agent Response:**
